# AutoQuant 빌드·배포 매뉴얼

> 대상 저장소: `S15P21A107`
> 작성 기준: 저장소의 Dockerfile, Docker Compose, Jenkinsfile, Spring/AI 설정 파일
> 비밀값은 저장소에 포함하지 않으며, 아래 문서에도 실제 값을 기록하지 않는다.

## 1. 시스템 구성

| 구분 | 구현 | 역할 |
| --- | --- | --- |
| Frontend | React 19, TypeScript, Vite 8, Nginx 1.27 | 사용자 화면 및 API/WebSocket 호출 |
| Backend API | Java 21, Spring Boot 3.5.16, Gradle | 인증, 전략, 백테스트·모의투자 API, WebSocket 중계 |
| Backtest worker | Spring Boot `backtest-worker` 프로필 | RabbitMQ 작업을 받아 백테스트 계산 및 결과 저장 |
| AI | Python 3.12, FastAPI, Uvicorn | 자연어 투자 아이디어를 전략 DSL로 변환 |
| Market ingest | Go 1.26 | Upbit 체결 수집, Kafka·Redis 처리, PostgreSQL 분봉 적재 |
| Data stores | PostgreSQL 16, Redis 7, Kafka 3.9, RabbitMQ 4.3 | 정본 데이터, 실시간 캐시, 수집 이벤트, 백테스트 작업 큐 |

운영은 Docker Compose로 구성한다. 외부 요청은 Nginx가 HTTPS로 받고, Frontend와 API를 각각 `127.0.0.1:3000`, `127.0.0.1:18080`으로 프록시한다. API와 Frontend는 외부에 직접 포트를 공개하지 않는다.

## 2. 사전 요구사항

### 개발·빌드 환경

| 항목 | 코드 기준 버전 |
| --- | --- |
| Docker Engine / Docker Compose plugin | Compose 파일 실행 가능 버전 |
| Java | 21 |
| Node.js | 20 |
| Python | 3.12 |
| Go | 1.26 |
| PostgreSQL | 16 |
| Redis | 7 |
| Kafka | 3.9.0 |
| RabbitMQ | 4.3.5-management-alpine |

운영 배포용 Go 이미지는 `linux/amd64`로 빌드된다. 운영 서버는 이에 맞는 Linux x86_64 환경이어야 한다.

### 운영 서버 준비

1. Docker Engine과 Docker Compose plugin을 설치한다.
2. Jenkins가 저장소를 체크아웃하고 Docker 이미지를 빌드·기동할 수 있도록 Docker 권한을 부여한다.
3. Nginx와 TLS 인증서를 준비하고 `infra/nginx/j15a107.p.ssafy.io.conf`의 도메인·인증서 경로를 운영 환경에 맞게 반영한다.
4. 운영 비밀값은 `/etc/a107/.env.production`에만 저장한다. Git에 커밋하지 않는다.

## 3. 환경변수

### 3.1 운영 필수값

다음 값은 `infra/docker-compose.prod.yml`에서 요구한다. 실제 값은 비밀 관리 위치에만 보관한다.

| 범주 | 변수 | 설명 |
| --- | --- | --- |
| 이미지 | `IMAGE_PREFIX`, `IMAGE_TAG` | Docker 이미지 저장소 접두사와 배포할 Git SHA 태그 |
| DB | `DB_NAME`, `DB_USER`, `DB_PASSWORD` | PostgreSQL 데이터베이스 및 계정 |
| 인증 | `JWT_SECRET` | 서비스 JWT 서명 키. 32바이트 이상 |
| RabbitMQ | `RABBITMQ_USERNAME`, `RABBITMQ_PASSWORD` | 작업 큐 연결 계정 |
| SSAFY SSO | `SSAFY_CLIENT_ID`, `SSAFY_CLIENT_SECRET`, `SSAFY_REDIRECT_URI` | OAuth2 클라이언트 등록값과 백엔드 콜백 URL |
| 서비스 주소 | `FRONTEND_BASE_URL` | 로그인 완료 후 이동할 Frontend URL |
| AI/GMS | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `APP_ENV` | GMS OpenAI 호환 게이트웨이 연결값 |
| 캔들 수집 | `CANDLE_HISTORY_FROM`, `CANDLE_HISTORY_REQUEST_BUDGET` | Upbit 과거 분봉 동기화 시작 시점과 실행당 요청 예산 |

### 3.2 선택값과 기본값

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `AUTH_COOKIE_SECURE` | `true` | HTTPS 쿠키 Secure 속성 |
| `LLM_TIMEOUT_SECONDS` | `30` | AI 서비스가 LLM 응답을 기다리는 최대 시간 |
| `MAX_RETRIES` | `2` | AI DSL 검증 실패 시 재시도 횟수 |
| `LOG_LEVEL` | `INFO` | AI 서비스 로그 레벨 |
| `CANDLE_SYNC_INTERVAL` | `5m` | 과거·최신 캔들 동기화 주기 |
| `UPBIT_REST_BASE_URL` | `https://api.upbit.com` | Upbit REST API 주소 |
| `UPBIT_REST_TIMEOUT` | `5s` | Upbit REST 요청 제한 시간 |
| `BACKTEST_WORKER_DB_POOL_MAX` | `3` | 워커 한 개가 쓰는 DB 연결 최대 수 |
| `BACKTEST_WORKER_JDBC_BATCH_SIZE` | `50` | 백테스트 결과 저장 JDBC 배치 크기 |

`backend/api/src/main/resources/application.yml`은 Backend의 설정 정본이며, `ai/app/core/config.py`는 AI 서비스의 설정 정본이다. `.env`, `/etc/a107/.env.production`과 실제 키·비밀번호는 절대 Git에 추가하지 않는다.

## 4. 로컬 빌드 및 검증

### 4.1 공통 인프라 기동

```bash
cp infra/.env.example infra/.env
docker compose -f infra/docker-compose.yml up -d
docker compose -f infra/docker-compose.yml ps
```

로컬 Compose는 PostgreSQL, Redis, Kafka, RabbitMQ를 기동한다. 스키마는 Backend가 Flyway로 생성한다.

### 4.2 모듈별 빌드·테스트

```bash
# Backend API
cd backend/api
./gradlew test --no-daemon
./gradlew build --no-daemon

# Frontend
cd ../../frontend
npm ci
npm run lint
npm run build

# AI
cd ../ai
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q

# Ingest
cd ../backend/ingest
go test ./...
go vet ./...
go build ./...
```

Windows에서는 Bash 활성화 명령 대신 PowerShell에 맞게 가상환경을 활성화한다. AI의 `pytest -m live`는 실제 GMS 크레딧을 소모하므로 기본 검증에는 포함하지 않는다.

### 4.3 Docker 이미지 빌드

저장소 루트에서 실행한다.

```bash
docker build -t a107/backend-api:<git-sha> -f backend/api/Dockerfile backend/api
docker build -t a107/ingest:<git-sha> -f backend/ingest/Dockerfile backend/ingest
docker build -t a107/ai:<git-sha> -f ai/Dockerfile ai
docker build -t a107/frontend:<git-sha> -f frontend/Dockerfile frontend
```

## 5. 운영 배포 절차

### 5.1 Jenkins 자동 배포

`develop` 브랜치 배포 시 Jenkinsfile은 다음 순서로 동작한다.

1. GitLab 저장소를 체크아웃하고 현재 커밋의 짧은 SHA를 `IMAGE_TAG`로 정한다.
2. Backend API, Frontend, AI, Ingest 테스트를 병렬로 실행한다.
3. 네 개 Docker 이미지를 빌드한다.
4. `infra/docker-compose.prod.yml`과 `/etc/a107/.env.production`으로 Compose를 기동한다.
5. Backtest worker를 기본 2개로 스케일한다.
6. Frontend·Backend HTTP 응답, 필수 컨테이너 상태, Kafka 초기화, Worker 실행 여부를 점검한다.
7. 최근 3개를 제외한 오래된 이미지 정리 작업을 수행한다.

### 5.2 수동 배포

Jenkins 장애 또는 운영 점검 시, Jenkins 작업 디렉터리 또는 저장소 루트에서 아래 명령으로 동일하게 기동한다.

```bash
export IMAGE_PREFIX=a107
export IMAGE_TAG=<배포할_커밋_SHA>

docker compose \
  --env-file /etc/a107/.env.production \
  -f infra/docker-compose.prod.yml \
  up -d --pull missing --remove-orphans \
  --scale backtest-worker=2

bash infra/verify-production-services.sh \
  infra/docker-compose.prod.yml \
  /etc/a107/.env.production
```

### 5.3 배포 후 확인

```bash
# 컨테이너 상태
docker compose \
  --env-file /etc/a107/.env.production \
  -f infra/docker-compose.prod.yml ps

# API·Frontend 상태 점검
bash infra/verify-production-services.sh \
  infra/docker-compose.prod.yml \
  /etc/a107/.env.production

# Worker 수와 RabbitMQ 소비자 수 확인
docker ps --filter "name=backtest-worker"
docker exec a107-rabbitmq rabbitmqctl list_queues name messages_ready messages_unacknowledged consumers
```

정상 조건은 Frontend HTTP 200, Backend HTTP 200 또는 인증 미포함 상태의 401, 필수 컨테이너 실행, Kafka 초기화 컨테이너의 성공 종료, Backtest worker 1개 이상 실행이다.

## 6. 데이터베이스와 주요 설정 파일

### 6.1 DB 접속과 스키마

PostgreSQL 접속 정보는 `DB_NAME`, `DB_USER`, `DB_PASSWORD`로 주입한다. 컨테이너 내부 접속 예시는 다음과 같다.

```bash
docker exec -it a107-postgres sh -c 'psql -X -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Flyway 마이그레이션의 단독 원본은 `backend/api/src/main/resources/db/migration/`이다. 주요 스키마는 다음과 같다.

| 스키마 | 주요 데이터 |
| --- | --- |
| `account` | SSAFY SSO 회원 |
| `reference` | Upbit KRW 마켓 자산 기준 정보 |
| `market_data` | 확정 분봉 |
| `ops` | 캔들 동기화 상태·수집 대상·롤업 작업 |
| `strategy` | 전략 DSL 및 버전 계보 |
| `trading` | 백테스트, 모의투자 실행·체결·자산 곡선·결과 |
| `contest` | 대회 회차·데이터셋·평가·랭킹 |
| `notification` | 알림 및 사용자 알림 설정 |

### 6.2 주요 프로퍼티 정의 파일

| 파일 | 역할 |
| --- | --- |
| `backend/api/src/main/resources/application.yml` | Backend API, DB, Redis, RabbitMQ, SSAFY OAuth, JWT, AI, Upbit, Worker 프로필 |

## 7. 장애 확인 순서

1. `docker compose ps`로 컨테이너가 실행 중인지 확인한다.
2. `infra/verify-production-services.sh`로 HTTP·컨테이너·Worker·Kafka 초기화를 확인한다.
3. API, AI, Ingest, Worker는 `docker logs <컨테이너명>`으로 최근 오류를 확인한다.
4. 백테스트 지연은 RabbitMQ의 `messages_ready`, `messages_unacknowledged`, `consumers`와 Worker 개수를 함께 확인한다.
5. 캔들 최신성 문제는 `ops.minute_candle_sync_state`, `market_data.minute_candle`의 최신 `open_time`을 확인한다.
