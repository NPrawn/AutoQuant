# AutoQuant 외부 서비스 사용 문서

> 실제 API 키·클라이언트 시크릿·OAuth 토큰은 이 문서와 저장소에 기록하지 않는다. 모든 비밀값은 운영 환경변수로 주입한다.

## 1. 외부 서비스 목록

| 서비스 | 사용 목적 | 인증 필요 여부 | 코드 연결 위치 |
| --- | --- | --- | --- |
| SSAFY SSO | 사용자 로그인 및 회원 식별 | 필요 | Backend `auth` 패키지 |
| SSAFY GMS OpenAI 호환 API | 자연어 전략을 JSON DSL 초안으로 변환 | 필요 | AI FastAPI 서비스 |
| Upbit Open API | KRW 마켓 정보, 분봉 이력, 실시간 체결 수집 | 공개 API, 별도 키 없음 | Backend `asset`, Go `ingest` |
| GitLab + Jenkins | 코드 변경 검증 및 운영 Docker 배포 | 운영 관리 권한 필요 | `Jenkinsfile` |
| Let's Encrypt / Nginx | 운영 도메인 HTTPS 종료 및 리버스 프록시 | 인증서 발급·갱신 권한 필요 | `infra/nginx/` |

## 2. SSAFY SSO

### 용도

사용자는 SSAFY OAuth2 Authorization Code 흐름으로 로그인한다. Backend가 인가 코드를 직접 받아 SSAFY 액세스 토큰으로 교환하고, 사용자 정보를 조회한 뒤 서비스 JWT를 발급한다. SSAFY 액세스·리프레시 토큰은 DB에 저장하지 않는다.

### 사전 준비

1. SSAFY 프로젝트 사이트에서 서비스용 OAuth 클라이언트를 등록한다.
2. Backend 콜백 URL을 `SSAFY_REDIRECT_URI`와 같은 값으로 등록한다.
3. 발급받은 Client ID와 Client Secret을 운영 비밀 환경에 저장한다.
4. 운영 Frontend 도메인을 `FRONTEND_BASE_URL`로 설정한다.

### 필수 환경변수

| 변수 | 설명 |
| --- | --- |
| `SSAFY_BASE_URL` | 기본값 `https://project.ssafy.com` |
| `SSAFY_CLIENT_ID` | SSAFY에서 발급한 클라이언트 ID |
| `SSAFY_CLIENT_SECRET` | SSAFY에서 발급한 클라이언트 시크릿 |
| `SSAFY_REDIRECT_URI` | 로그인 완료 후 인가 코드를 받는 Backend 콜백 URL |

### 동작 확인

1. Frontend 로그인 화면에서 SSAFY 로그인 버튼을 누른다.
2. Backend `GET /auth/ssafy/authorize-url`이 인가 URL을 반환하는지 확인한다.
3. SSAFY 로그인 후 `GET /auth/ssafy/callback`으로 돌아오는지 확인한다.
4. 성공 시 `access_token` httpOnly 쿠키가 발급되고 Frontend로 이동하는지 확인한다.

## 3. SSAFY GMS OpenAI 호환 API

### 용도

사용자가 입력한 자연어 투자 아이디어를 전략 DSL(JSON) 초안으로 변환한다. AI 서비스는 FastAPI로 독립 실행되며, DB·Redis·인증 정보를 직접 다루지 않는다. Spring Backend만 AI 서비스에 HTTP 요청을 보낸다.

### 사전 준비

1. 팀에 할당된 GMS API 키와 사용 가능한 모델명을 확인한다.
2. AI 서비스용 환경변수에 GMS 게이트웨이 주소, 키, 모델명을 주입한다.
3. 실제 호출 전 `/health`로 AI 컨테이너 기동 상태를 확인한다. 이 엔드포인트는 LLM을 호출하지 않는다.

### 필수 환경변수

| 변수 | 설명 |
| --- | --- |
| `LLM_BASE_URL` | GMS OpenAI 호환 API 기본 주소. 예: `https://gms.ssafy.io/gmsapi/api.openai.com/v1` |
| `LLM_API_KEY` | GMS에서 발급받은 팀 API 키 |
| `LLM_MODEL` | 사용할 GMS 모델 식별자 |
| `APP_ENV` | 실행 환경 구분값 |

### 선택 환경변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `LLM_TIMEOUT_SECONDS` | 30 | GMS 응답 대기 시간 |
| `MAX_RETRIES` | 2 | DSL 검증 실패 시 재시도 횟수 |
| `LOG_LEVEL` | INFO | AI 서비스 로그 레벨 |

### 호출 흐름과 제한

1. Frontend가 Backend `POST /api/ai/strategies/translate`를 호출한다.
2. Backend가 AI 서비스 `POST /api/v1/ai/strategies/translate`를 호출한다.
3. AI 서비스가 GMS로 요청해 DSL 초안을 검증한다.
4. Backend는 회원별 분당 10회, AI 서비스는 프로세스 전체 분당 30회로 호출량을 제한한다.
5. GMS 장애가 연속될 경우 AI 서비스의 서킷 브레이커가 추가 호출을 잠시 차단한다.

`pytest -m live`는 실제 GMS 호출과 크레딧 사용이 발생하므로 기본 CI 테스트에서 제외한다.

## 4. Upbit Open API

### 용도

AutoQuant는 Upbit KRW 마켓을 대상으로 한다.

- Backend: 마켓 목록과 자산 등록 시 거래지원 기간 정보를 조회한다.
- Go Producer: Upbit WebSocket 실시간 체결을 수집한다.
- Go Backfill: Upbit REST 분봉을 수집·보정한다.
- Frontend: Backend가 제공하는 REST·WebSocket을 통해 시세와 차트를 본다. Frontend가 Upbit를 직접 호출하지 않는다.

### 사용 주소

| 구분 | 기본 주소 |
| --- | --- |
| REST | `https://api.upbit.com` |
| WebSocket | `wss://api.upbit.com/websocket/v1` |

공개 시세 API만 사용하므로 Upbit 개인 API 키나 실제 주문 권한은 필요하지 않다.

### 관련 환경변수

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `UPBIT_REST_BASE_URL` | `https://api.upbit.com` | Backfill REST API 주소 |
| `UPBIT_REST_TIMEOUT` | `5s` | Backfill REST 요청 제한 시간 |
| `UPBIT_BASE_URL` | `https://api.upbit.com` | Backend 자산 조회 API 주소 |
| `UPBIT_TIMEOUT` | `5s` | Backend Upbit 요청 제한 시간 |
| `UPBIT_WEBSOCKET_URL` | `wss://api.upbit.com/websocket/v1` | Producer 실시간 체결 WebSocket 주소 |

### 운영 유의사항

- Upbit 호출 제한을 고려해 Backfill은 실행당 요청 예산을 두고 반복 수행한다.
- 데이터 수집 실패는 서비스 DB의 기존 확정 분봉을 삭제하지 않는다.
- 실시간 체결은 Kafka에 원본 이벤트로 전달하고, 확정 분봉은 PostgreSQL에 저장한다.

## 5. GitLab과 Jenkins

### 용도

GitLab은 형상관리와 Jenkins 소스 체크아웃 대상이다. Jenkins는 `develop` 배포에서 테스트, 이미지 빌드, Docker Compose 배포, 스모크 테스트를 수행한다.

### 사전 준비

1. Jenkins에 GitLab 저장소 접근 권한을 설정한다.
2. GitLab에서 Jenkins 빌드 트리거가 동작하도록 연동한다.
3. Jenkins 실행 계정이 Docker 명령과 `/etc/a107/.env.production` 읽기 권한을 갖도록 설정한다.
4. Jenkins 환경에서 `IMAGE_PREFIX=a107`, Worker replica 기본값 2를 유지한다.

### 코드 기준 파이프라인

`Jenkinsfile`은 Backend API, Frontend, AI, Ingest 테스트를 병렬 실행한 뒤 네 개 이미지를 빌드하고, 운영 Compose를 기동한다. 마지막에는 `infra/verify-production-services.sh`로 배포 상태를 점검한다.

## 6. Nginx와 Let's Encrypt

### 용도

Nginx는 외부 HTTPS 요청을 받고 내부 컨테이너로 전달한다.

| 경로 | 전달 대상 |
| --- | --- |
| `/` | Frontend `127.0.0.1:3000` |
| `/api/` | Backend `127.0.0.1:18080` |
| `/ws` | Backend WebSocket `127.0.0.1:18080` |
| `/gitlab-webhook/` | Jenkins Webhook `127.0.0.1:8080` |

### 사전 준비

1. 도메인 DNS를 운영 서버로 연결한다.
2. Let's Encrypt 인증서를 발급하고 Nginx 설정의 인증서 경로를 맞춘다.
3. HTTP 80 포트는 HTTPS 443으로 리다이렉트한다.
4. `/ws`에 WebSocket Upgrade 헤더와 충분한 read timeout을 설정한다.
