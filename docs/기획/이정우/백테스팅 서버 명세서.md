## 1. 목적

사용자가 생성한 `StrategyVersion`의 Strategy DSL을 과거 시장 데이터에 적용하여 전략의 성과를 검증한다.

백테스팅 서버는 전략을 직접 생성하거나 투자 판단을 변경하지 않고, 전달받은 전략을 과거 시간축에서 동일한 규칙으로 실행한다.

---

## 2. 전략 실행 구조

MVP 전략은 다음 흐름으로 실행한다.

```
업비트 KRW 거래대금 상위 30종목
                ↓
              Filter
                ↓
             Ranking
                ↓
              Top N
                ↓
            동일 비중
                ↓
           Rebalancing
```

### Universe

- 업비트 KRW 마켓
- 거래대금 상위 30종목
- 사용자가 직접 종목을 선택하지 않음
- 리밸런싱 시점에 다시 Universe 계산

> 거래대금 TOP 30의 거래대금 산정 기간은 추후 확정한다.
>

## 3. Factor Engine

MVP에서는 다음 6개 Factor를 지원한다.

| Factor | 주요 용도 |
| --- | --- |
| N-period Return | Filter / Ranking |
| RSI | Filter |
| SMA Disparity | Filter / Ranking |
| Volatility | Filter / Ranking |
| Volume Ratio | Filter |
| Drawdown | Filter / Ranking |

Factor 계산 모듈은 추후 새로운 Factor를 추가할 수 있도록 확장 가능한 구조로 구현한다.

```
Factor Engine
├── Return
├── RSI
├── SMA Disparity
├── Volatility
├── Volume Ratio
└── Drawdown
```

## 4. Filter / Ranking / Selection

### Filter

각 코인의 Factor 값을 계산하여 조건을 만족하지 않는 코인을 제외한다.

지원 연산:

```
>, <, >=, <=
AND, OR
```

예:

```
RSI(14) < 70
AND
VOLUME_RATIO(20) > 1.2
```

### Ranking

Filter를 통과한 코인을 하나의 Factor 기준으로 정렬한다.

예:

```
RETURN(20) DESC
VOLATILITY(20) ASC
```

`ASC / DESC`는 Ranking 방향을 의미한다.

### Selection

Ranking 결과에서 사용자가 설정한 `Top N` 종목을 실제 투자 대상으로 선택한다.

예:

```
Top 3
Top 5
Top 10
```

---

## 5. Portfolio / Rebalancing

MVP에서는 Top N 종목을 동일 비중으로 구성한다.

예:

```
Top 5
→ 종목당 목표 비중 20%
```

리밸런싱 시점마다 새로운 Top N을 계산하고 현재 Portfolio와 목표 Portfolio의 차이를 주문으로 변환한다.

```
현재 Portfolio
        ↓
Universe 재계산
        ↓
Filter / Ranking
        ↓
새로운 Top N
        ↓
동일비중 Target Portfolio
        ↓
현재 비중과 목표 비중 비교
        ↓
가상 매수 / 매도
```

Top N에서 탈락한 종목은 매도한다.

Top N에 계속 포함된 종목도 가격 변화로 목표 비중에서 벗어난 경우 다시 동일 비중에 맞춰 조정한다.

## 6. 시간 처리

기존 MVP 기획에 따라 시장 데이터의 기본 Timeframe은 `1시간봉`으로 한다.

Strategy DSL의 `period`는 Candle 개수를 의미한다.

예:

```
RETURN(20)
→ 최근 20개 1시간봉 기준 수익률

RSI(14)
→ 최근 14개 1시간봉 기준 RSI
```

향후 다른 Timeframe을 지원할 경우 `period` 역시 해당 Timeframe의 Candle 개수를 기준으로 해석한다.

### Rebalancing

시장 데이터 Timeframe과 Rebalancing 주기는 별도로 관리한다.

```
1시간봉 데이터 지속 처리
        ↓
Portfolio 평가
        ↓
Rebalancing 시점 도달
        ↓
Universe / Filter / Ranking
        ↓
Top N 재선정
```

Portfolio 가치는 매 Candle마다 계산하고, 종목 재선정은 Rebalancing 시점에만 수행한다.

## 7. Look-Ahead 방지

백테스트 시점 이후의 데이터를 Factor 계산에 사용할 수 없도록 한다.

```
Candle t 종료
      ↓
Factor 계산
      ↓
Filter / Ranking
      ↓
주문 결정
      ↓
Candle t+1에서 가상 체결
```

Factor 계산에 과거 데이터가 추가로 필요한 경우 Warm-up 데이터를 조회한다.

Warm-up 데이터는 지표 계산에만 사용하며 해당 기간에는 거래를 수행하지 않는다.

> 실제 체결 기준 가격은 `다음 Candle Open`을 기본안으로 하며 최종 체결 정책은 추후 확정한다.
>

## 8. 가상 체결

리밸런싱 결과를 기준으로 가상 주문을 생성한다.

체결 시 다음 요소를 반영한다.

- 거래 수수료
- Slippage
- 최소 주문금액
- 가격 / 수량 정밀도

```
Target Portfolio 계산
        ↓
주문 생성
        ↓
가상 체결가격 계산
        ↓
Slippage 적용
        ↓
거래소 주문 조건 검증
        ↓
Fee 적용
        ↓
Portfolio 갱신
```

투자 방향 및 전략 판단은 Strategy DSL 또는 Strategy Engine의 결과를 그대로 따른다.

## 10. 실행 방식

백테스트는 비동기 Job으로 처리한다.

```
QUEUED
   ↓
RUNNING
   ↓
COMPLETED

또는

FAILED
```

백테스트 실행 시 다음 정보를 저장한다.

```
BacktestRun
- backtestId
- strategyVersionId
- startTime
- endTime
- initialCapital
- status
- queuedAt
- startedAt
- completedAt
- engineVersion
- marketDataVersion
```

동일한 StrategyVersion, MarketDataVersion, EngineVersion 및 실행 설정에서는 동일한 결과가 생성되도록 한다.
