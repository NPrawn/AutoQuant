# 랭킹형 투자전략 시스템 설계안

## 1. 전략 방식

### 랭킹형 전략이란?

랭킹형 전략은 사용자가 특정 코인을 직접 선택하고 매수·매도 시점을 지정하는 방식이 아니라, **여러 코인을 동일한 기준으로 평가하여 투자할 종목을 자동으로 선정하는 방식**이다.

전체적인 흐름은 다음과 같다.

```text
업비트 KRW 거래대금 상위 30종목
                ↓
              Filter
                ↓
        조건에 맞는 종목만 통과
                ↓
              Ranking
                ↓
        특정 Factor 기준 정렬
                ↓
              Top N
                ↓
             동일 비중 투자
                ↓
            Rebalancing
                ↓
        일정 주기마다 다시 평가
```

예를 들어 다음과 같은 전략을 만들 수 있다.

```text
[Filter]

RSI(14) < 70
AND
VOLUME_RATIO(20) > 1.2

        ↓

[Ranking]

RETURN(20) 높은 순

        ↓

[Selection]

Top 5

        ↓

[Allocation]

동일 비중

        ↓

[Rebalancing]

매주
```

이를 자연어로 표현하면 다음과 같다.

> 과매수 상태가 아니면서 평소보다 거래량이 많은 코인만 후보로 선정하고, 그중 최근 20기간 수익률이 높은 5개 코인에 동일 비중으로 투자한다. 이후 매주 다시 평가하여 투자 종목을 변경한다.

---

## 2. 투자 대상 Universe

MVP에서는 사용자가 Universe를 직접 설정하지 않는다.

```text
업비트 KRW 마켓
+
거래대금 상위 30종목
```

으로 고정한다.

Universe는 **실제로 투자할 종목을 의미하는 것이 아니라 Filter와 Ranking을 수행할 최초 후보군**이다.

```text
거래대금 상위 30개
        ↓
      Filter
        ↓
예: 18개 통과
        ↓
      Ranking
        ↓
      Top 5
        ↓
실제 투자 종목 5개
```

따라서 어떤 코인을 실제로 투자할지는 사용자가 직접 지정하지 않고 **사용자가 만든 전략에 따라 결정된다.**

---

## 3. Filter

Filter는 30개의 후보 종목 중 **사용자가 설정한 조건을 만족하지 않는 종목을 제거하는 단계**이다.

예를 들어:

```text
RSI(14) < 70
```

이라면 RSI가 70 이상인 종목은 Ranking 후보에서 제외한다.

여러 조건을 `AND / OR`로 조합할 수도 있다.

```text
RSI(14) < 70
AND
VOLATILITY(20) < 8%
```

```text
30종목
   ↓
RSI 조건 검사
   ↓
변동성 조건 검사
   ↓
조건을 만족한 종목만 Ranking으로 전달
```

### Filter에서 제공할 연산

#### Comparison

```text
>
<
>=
<=
```

#### Logic

```text
AND
OR
```

MVP에서는 조건식을 무제한으로 복잡하게 만들기보다는 조건 개수 또는 중첩 깊이에 제한을 둘 수 있다.

---

## 4. Ranking

Filter를 통과한 코인들을 **하나의 Factor를 기준으로 서로 비교하여 순위를 결정**한다.

예를 들어:

```text
Ranking
RETURN(20) 높은 순
```

이라고 설정했다고 하자.

Filter를 통과한 종목의 값이:

| 종목 | RETURN(20) |
| --- | ---: |
| BTC | +12% |
| ETH | +7% |
| XRP | +18% |
| SOL | -3% |
| DOGE | +10% |

이라면:

```text
1위 XRP    +18%
2위 BTC    +12%
3위 DOGE   +10%
4위 ETH     +7%
5위 SOL     -3%
```

가 된다.

이처럼 **각 코인의 과거 데이터를 이용해 Factor를 계산한 후 동일 시점에서 여러 코인의 Factor 값을 비교**한다.

---

## 5. Top N Selection

Ranking 결과 중 사용자가 설정한 상위 N개 종목을 실제 투자 대상으로 선정한다.

예:

```text
Top N = 5
```

이면 Ranking 결과의 1~5위 종목을 선택한다.

```text
Ranking

1 XRP ─┐
2 BTC  │
3 ETH  ├─ 투자
4 SOL  │
5 ADA ─┘
──────────
6 DOGE
7 AVAX
...
```

Top N의 범위는 서비스에서 제한한다.

예:

```text
Top 3
Top 5
Top 10
```

---

## 6. 자산 배분

MVP에서는 **동일 비중으로 고정**한다.

예를 들어 투자금이 100만 원이고 Top 5 전략이라면:

```text
1위 → 20만원
2위 → 20만원
3위 → 20만원
4위 → 20만원
5위 → 20만원
```

특정 종목을 사용자가 직접 50%, 30%, 20% 등으로 설정하지 않는다.

어떤 코인이 Top N에 들어갈지 사전에 알 수 없기 때문에 랭킹형 전략에서는 동일 비중 방식이 자연스럽다.

---

## 7. Rebalancing

사용자가 설정한 주기마다 **Filter와 Ranking을 다시 수행하여 Top N을 재선정**한다.

예를 들어 매주 리밸런싱한다고 가정한다.

### 기존 Top 5

```text
BTC
ETH
XRP
SOL
ADA
```

### 다음 리밸런싱 시점 Top 5

```text
BTC
ETH
XRP
DOGE
AVAX
```

그러면:

```text
유지
BTC
ETH
XRP

매도
SOL
ADA

매수
DOGE
AVAX
```

가 된다.

즉 별도의 복잡한 매도 조건 없이 **Top N에서 탈락하는 것이 기본적인 매도 조건**이 된다.

---

## 8. Factor 선정 기준

MVP에서는 많은 기술적 지표를 제공하는 것보다 **서로 다른 투자 판단 요소를 대표하면서 사용자가 이해하기 쉬운 Factor를 선정**한다.

선정 기준은 다음과 같다.

1. 실제 투자 전략에서 의미 있게 사용되는가
2. 서로 가격이 다른 코인 간 비교가 가능한가
3. 기존 Factor와 역할이 지나치게 중복되지 않는가
4. 사용자가 비교적 쉽게 이해할 수 있는가
5. Filter 또는 Ranking에서 실제 전략 조합에 활용할 수 있는가

이를 기준으로 다음 **6개 Factor**를 우선 사용한다.

| 분류 | Factor | 핵심 의미 | 주요 용도 |
| --- | --- | --- | --- |
| Momentum / Performance | **N-period Return** | 최근 N기간 동안 얼마나 상승·하락했는가 | Filter / **Ranking** |
| Momentum | **RSI** | 최근 가격 움직임이 과열/과매도 상태인가 | **Filter** |
| Trend | **SMA Disparity** | 현재 가격이 이동평균에서 얼마나 떨어져 있는가 | **Filter** / Ranking |
| Volatility | **Volatility** | 가격이 얼마나 크게 흔들리는가 | Filter / **Ranking** |
| Volume | **Volume Ratio** | 현재 거래량이 평소보다 얼마나 많은가 | **Filter** |
| Risk | **Drawdown** | 최근 고점에서 얼마나 하락했는가 | Filter / Ranking |

`Filter / Ranking` 사용 범위는 MVP 구현 과정에서 최종 확정한다.

## 9. Factor 상세

### 9.1 N-period Return

#### 의미

현재 가격이 N기간 전 가격에 비해 얼마나 상승하거나 하락했는지를 나타낸다.

#### 계산

```text
RETURN(N)
= (현재 가격 - N기간 전 가격) / N기간 전 가격 × 100
```

예:

```text
20기간 전 가격 = 100
현재 가격 = 115

RETURN(20) = +15%
```

#### 활용

대표적인 **Ranking Factor**로 사용할 수 있다.

```text
RETURN(20) 높은 순
```

이면 최근 20기간 동안 상대적으로 많이 상승한 코인을 우선한다.

예:

```text
XRP   +18%
BTC   +13%
ETH    +8%
SOL    +3%

→ XRP > BTC > ETH > SOL
```

반대로:

```text
RETURN(5) 낮은 순
```

처럼 설정하는 것도 가능하다.

#### 해석

`RETURN 높은 순`은 최근 상대적으로 강한 가격 흐름이 지속될 수 있다는 **모멘텀 아이디어**를 표현할 수 있다.

---

### 9.2 RSI

#### 의미

최근 상승과 하락 움직임의 상대적인 강도를 0~100 사이 값으로 표현한다.

일반적으로 높은 값은 최근 상승 움직임이 강했다는 것을, 낮은 값은 최근 하락 움직임이 강했다는 것을 의미한다.

#### 대표적인 기준

```text
RSI > 70
→ 일반적으로 과매수 구간으로 해석하는 경우가 많음

RSI < 30
→ 일반적으로 과매도 구간으로 해석하는 경우가 많음
```

이는 절대적인 매수·매도 법칙이 아니라 널리 사용되는 참고 기준이다.

#### 활용

랭킹보다는 **Filter에 활용하기 직관적**이다.

```text
RSI(14) < 70
```

→ RSI가 70 이상인 종목을 후보에서 제외

또는:

```text
RSI(14) < 40
```

→ 상대적으로 RSI가 낮은 종목만 후보로 선정

---

### 9.3 SMA Disparity

#### 의미

현재 가격이 N기간 단순이동평균(SMA)에서 얼마나 떨어져 있는지를 나타낸다.

기존 신호형에서는:

```text
SMA(20) > SMA(60)
```

처럼 동일 종목의 이동평균끼리 비교할 수 있었다.

하지만 랭킹형에서는:

```text
BTC SMA(20) = 100,000,000원
XRP SMA(20) = 3,000원
```

처럼 **코인마다 가격 단위가 다르기 때문에 SMA 절대값 자체를 종목 간 비교하기 어렵다.**

따라서 현재 가격과 SMA의 관계를 비율로 변환한다.

예를 들어 이격률 방식이라면:

```text
SMA_DISPARITY(N)
= (현재 가격 / SMA(N) - 1) × 100
```

예:

```text
BTC    +5%
ETH    +2%
XRP    -3%
```

처럼 표현할 수 있다.

#### 활용

```text
SMA_DISPARITY(20) > 0%
```

→ 현재 가격이 20기간 SMA보다 높은 코인만 선정

또는 Ranking을 허용한다면:

```text
SMA_DISPARITY(20) 높은 순
```

→ 이동평균보다 상대적으로 더 위에 위치한 종목 우선

---

### 9.4 Volatility

#### 의미

일정 기간 동안 가격 수익률이 얼마나 크게 변했는지를 나타낸다.

값이 높을수록 가격 움직임이 크고, 낮을수록 상대적으로 안정적이다.

MVP에서는 정확한 계산 정의를 하나로 고정해야 한다. 예를 들어 **N기간 수익률의 표준편차**를 사용하는 방식이 가능하다.

#### 활용 — Filter

```text
VOLATILITY(20) < 8%
```

→ 변동성이 지나치게 높은 코인을 제외

#### 활용 — Ranking

```text
VOLATILITY(20) 낮은 순
```

→ 상대적으로 가격 변동이 작은 코인을 우선

예:

```text
BTC    3.2%
ETH    4.8%
XRP    7.1%

낮은 순
→ BTC > ETH > XRP
```

---

### 9.5 Volume Ratio

#### 의미

현재 거래량이 최근 평균 거래량과 비교해 어느 정도인지를 나타낸다.

#### 계산 예시

```text
VOLUME_RATIO(N)
= 현재 거래량 / 최근 N기간 평균 거래량
```

예:

```text
최근 20기간 평균 거래량 = 100
현재 거래량 = 150

VOLUME_RATIO(20) = 1.5
```

즉 평소의 약 1.5배 수준의 거래량이라는 의미다.

#### 활용

주로 **Filter**로 사용한다.

```text
VOLUME_RATIO(20) > 1.2
```

→ 최근 평균보다 거래량이 20% 이상 증가한 코인만 후보로 선정

단순 Volume 절대값 대신 Ratio를 사용하는 이유 역시 코인별 거래 규모 차이를 정규화하기 위해서다.

---

### 9.6 Drawdown

#### 의미

일정 기간 내 고점과 비교하여 현재 가격이 얼마나 하락해 있는지를 나타낸다.

예를 들어 최근 60기간의 최고 가격이 100이고 현재 가격이 80이라면:

```text
고점 = 100
현재 = 80

Drawdown = -20%
```

즉 최근 고점 대비 20% 하락한 상태다.

#### 활용 — Filter

예:

```text
DRAWDOWN(60) > -20%
```

→ 최근 고점 대비 20%보다 더 크게 하락한 종목은 제외

Drawdown의 부호를 `-20%`로 표현할지 `20%`의 양수 낙폭으로 표현할지는 DSL 설계 시 하나로 통일해야 한다.

#### 활용 — Ranking

정책에 따라:

```text
DRAWDOWN(60) 작은 종목 우선
```

처럼 상대적으로 낙폭이 작은 종목을 우선하는 방식도 가능하다.

## 10. Factor를 조합한 전략 예시

### 예시 1. 모멘텀 전략

```text
[Filter]

RSI(14) < 70

[Ranking]

RETURN(20) 높은 순

[Selection]

Top 5

[Rebalancing]

매주
```

#### 의미

> 과도하게 높은 RSI를 보이는 종목을 제외하고 최근 20기간 수익률이 높은 5개 종목을 선택한다.

---

### 예시 2. 거래량 + 추세 전략

```text
[Filter]

VOLUME_RATIO(20) > 1.2
AND
SMA_DISPARITY(20) > 0%

[Ranking]

RETURN(20) 높은 순

[Selection]

Top 5
```

#### 의미

> 최근 평균보다 거래량이 증가했고 현재 가격이 20기간 이동평균 위에 있는 종목만 남긴 뒤, 최근 수익률이 높은 5개를 선택한다.

---

### 예시 3. 저변동성 전략

```text
[Filter]

RSI(14) < 70

[Ranking]

VOLATILITY(20) 낮은 순

[Selection]

Top 5
```

#### 의미

> RSI가 지나치게 높은 종목을 제외하고 상대적으로 변동성이 낮은 5개 종목을 선택한다.

---

### 예시 4. 위험 제한 + 모멘텀 전략

```text
[Filter]

DRAWDOWN(60) > -20%
AND
VOLATILITY(20) < 10%

[Ranking]

RETURN(20) 높은 순

[Selection]

Top 5
```

#### 의미

> 최근 고점 대비 낙폭이 지나치게 크거나 변동성이 높은 종목을 제외한 뒤, 최근 수익률이 높은 종목을 선택한다.

## 11. 사용자 전략 생성 화면의 큰 흐름

사용자에게 `Factor`, `Cross-sectional` 같은 전문 용어부터 보여주기보다는 **투자 판단 순서대로 안내하는 방식**을 고려한다.

```text
① 어떤 코인을 후보로 남길까요?

[ RSI ] [ 14 ] [ < ] [ 70 ]
                AND
[ 거래량 비율 ] [ 20 ] [ > ] [ 1.2 ]

              ↓

② 남은 코인의 순위를 어떻게 정할까요?

[ 20기간 수익률 ]

[ 높은 순 ▼ ]

              ↓

③ 몇 개의 코인에 투자할까요?

[ Top 5 ▼ ]

              ↓

④ 언제 다시 종목을 선정할까요?

[ 매주 ▼ ]

              ↓

⑤ 백테스트
```

Universe와 동일비중 등 서비스가 고정한 정책은 사용자가 직접 설정할 필요가 없다.

## 12. 내부 Strategy DSL

사용자가 만든 전략은 코드로 직접 생성하는 것이 아니라 **JSON 기반 Strategy DSL로 변환하여 저장**한다.

예:

```json
{
  "filters": {
    "logic": "AND",
    "conditions": [
      {
        "factor": "RSI",
        "period": 14,
        "operator": "LT",
        "value": 70
      },
      {
        "factor": "VOLUME_RATIO",
        "period": 20,
        "operator": "GT",
        "value": 1.2
      }
    ]
  },
  "ranking": {
    "factor": "RETURN",
    "period": 20,
    "direction": "DESC"
  },
  "selection": {
    "topN": 5
  },
  "rebalance": {
    "period": "WEEKLY"
  }
}
```

실행 흐름은:

```text
사용자 UI
   ↓
Strategy DSL
   ↓
Strategy Validator
   ↓
Factor 계산
   ↓
Filter Engine
   ↓
Ranking Engine
   ↓
Top N
   ↓
동일비중 Portfolio
   ↓
Backtest / Paper Trading
```

이 구조를 통해 백테스트와 모의투자에서 동일한 전략 정의와 평가 로직을 재사용한다.

## 13. MVP 핵심 방향

이번 MVP에서 중요한 것은 **많은 투자 지표를 제공하는 것 자체가 아니다.**

핵심 사용자 경험은:

> **사용자가 자신의 투자 아이디어를 조건으로 표현하고 → 조건에 맞는 코인을 걸러내고 → 원하는 기준으로 순위를 매기고 → 실제 과거 데이터에서 전략을 검증하는 것**

이다.

따라서 초기에는 다음 6개 Factor를 중심으로 구현한다.

```text
N-period Return
RSI
SMA Disparity
Volatility
Volume Ratio
Drawdown
```

추후 필요하면:

```text
ADX
NATR
MFI
Bollinger Band Width
OBV
Donchian 계열
...
```

등을 확장할 수 있도록 Factor 계산 모듈을 확장 가능한 구조로 설계한다.

**랭킹형을 채택한 핵심 이유는 조건식의 자유도를 없애기 위해서가 아니라, 사용자가 만든 조건식을 `Filter → Ranking → Top N`이라는 명확한 흐름 안에서 사용할 수 있도록 가이드하기 위해서다.**

이를 통해 단순히 코드를 블록으로 바꾸는 노코드 도구보다는, 사용자가 투자 아이디어를 쉽게 구성하고 바로 백테스트·모의투자로 검증할 수 있는 전략 설계 환경을 목표로 한다.
