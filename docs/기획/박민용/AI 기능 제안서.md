# AI 기능 제안서

> 이 문서는 팀 공유용 요약이다. 상세 근거는 `ai/docs/DECISIONS.md`, 구현 계획은 `ai/docs/PLAN.md`에 있다.

## 1. 한 줄 소개

**사용자가 한국어로 설명한 투자 전략을 검증된 전략 DSL(JSON)로 바꾸고, 그 전략이 얼마나 과최적화됐는지 점수로 알려주는 AI 서버**

---

## 2. 왜 필요한가

퀀트 전략 빌더의 진입 장벽은 두 군데에 있다.

**첫째, 전략을 입력하는 방법.** 대부분의 백테스트 도구는 사용자에게 폼을 채우게 한다. 유니버스 선택, 지표 선택, 파라미터 입력, 리밸런싱 주기 선택. 전략 하나를 넣는 데 화면 서너 개를 지나야 하고, 그 화면은 이미 도메인을 아는 사람만 채울 수 있다.

사람은 전략을 이렇게 말한다.

```
거래대금 상위 20개 코인 중에서
최근 20일 수익률이 가장 높은 5개를 골라
동일비중으로 주간 리밸런싱하고
손절은 -10%로 걸어줘
```

이 문장 하나가 폼 열몇 칸에 해당한다. **자연어를 DSL로 옮기는 일이 역할 1이다.**

**둘째, 나온 결과를 믿어도 되는지.** 백테스트는 파라미터를 조금씩 바꿔가며 돌리면 언젠가 좋은 숫자가 나온다. 그 숫자가 전략의 실력인지 과거 데이터에 맞춘 결과인지 초보 사용자는 구분하지 못한다. **전략의 견고성을 점수로 알려주는 것이 역할 2다.**

---

## 3. 두 가지 역할

| 역할 | 하는 일 | 출력 | 상태 |
| --- | --- | --- | --- |
| **역할 1** | 자연어 → 전략 DSL 변환 | `Strategy` JSON + 메타 | 이번 5주 범위 |
| **역할 2** | 전략의 견고성(과최적화 정도) 추론 | 점수 | 범위 밖, 자리만 비워 둠 |

역할 2를 지금 만들지 않는 이유는 학습 데이터가 없기 때문이다. 견고성 모델을 학습시키려면 전략 수천 개와 각각의 백테스트 결과가 필요하고, 그건 백테스트 엔진이 돌아간 뒤에야 모을 수 있다.

대신 **응답의 `meta.warnings` 자리를 지금 비워 둔다.** 현재는 규칙이 채우고, 모델이 완성되면 같은 자리를 점수가 채운다. API 형태를 바꾸지 않고 내용만 갈아끼우는 구조다.

---

## 4. 기능 1 — 자연어 전략 변환

### 동작 흐름

```
사용자 자연어 입력
        ↓
Spring Backend
        ↓
POST /api/v1/ai/strategies/translate
        ↓
AI 서버
        ↓
프롬프트 조립 (DSL 스키마 주입)
        ↓
LLM 호출 (SSAFY GMS 게이트웨이)
        ↓
JSON 파싱 → 스키마 검증
        ↓
실패 시 오류를 붙여 재시도 (최대 2회)
        ↓
Strategy JSON + meta
        ↓
Spring → 백테스트 엔진
```

### 입력 예시와 출력

입력:

```
거래대금 상위 20개 코인 중에서 최근 20일 수익률이 가장 높은 5개를
골라 동일비중으로 주간 리밸런싱하고, 손절은 -10%로 걸어줘
```

출력 (필드명과 허용값은 **임시 스키마** 기준이다. 전략 도메인 명세가 확정되면 교체된다):

```json
{
  "universe":  { "market": "UPBIT_KRW", "top_by_trading_value": 20 },
  "signal":    { "type": "CROSS_SECTIONAL_RANK",
                 "feature": { "type": "RETURN", "lookback_days": 20 },
                 "select_top": 5 },
  "portfolio": { "type": "EQUAL_WEIGHT", "max_asset_weight": 0.34 },
  "risk":      { "stop_loss": -0.1, "take_profit": null },
  "execution": { "rebalance": "WEEKLY", "timeframe": "1D" }
}
```

## 5. 기능 2 — 전략 수정

같은 엔드포인트가 신규 생성과 수정을 겸한다. 요청에 현재 전략이 실려 오면 수정, 없으면 생성이다.

```
현재 전략 + "손절을 -5%로 바꿔줘"
        ↓
수정된 전략 + changes 목록
```

엔드포인트를 나누지 않는 이유는 프롬프트와 검증 경로가 같기 때문이다. 나누면 두 벌을 관리하게 된다.

---

## 6. 기능 3 — 임의 결정 알림 (`assumptions`)

사용자가 전략을 다 말해 주지 않는다.

```
"돈 많이 버는 전략 만들어 줘"
```

이런 입력을 거절하지 않고 기본값으로 채워 전략을 만든다. 대신 **무엇을 임의로 정했는지 응답에 담는다.**

```json
"meta": {
  "assumptions": [
    "리밸런싱 주기를 언급하지 않아 주간으로 설정했습니다.",
    "순위 기준을 언급하지 않아 20일 수익률로 설정했습니다."
  ]
}
```

거절하는 편이 정직해 보이지만, 사용자 입장에서는 아무것도 못 얻는다. 기본값으로 채우고 채운 사실을 알리는 쪽이 낫다. 화면에서는 "이 값들은 제가 정했어요" 정도로 보여주면 된다.

## 7. 기능 4 — 세 층 검증

LLM 출력을 통과시킬지 말지를 세 층으로 나눈다.

| 층 | 무엇을 잡나 | 처리 |
| --- | --- | --- |
| **거부** | 표현이 불가능하거나 LLM이 명백히 틀린 것 | 재시도, 소진 시 422 |
| **경고** | 유효하지만 전략적으로 위험한 것 | 200으로 통과, `meta.warnings`에 기록 |
| **방치** | 나머지 | 아무것도 안 함 |

판단 기준은 하나다.

> **결과가 조용히 틀리는 것만 막고, 나쁘게 나오지만 사용자가 배울 수 있는 것은 막지 않는다.**

막는 예 — LLM이 "20일"을 20시간으로 옮기는 것. 사용자가 결과를 봐도 뭐가 잘못됐는지 알 수 없다.

막지 않는 예 — 손절을 -1%로 거는 것. 계속 손절당하는 걸 보고 사용자가 조정한다. 백테스트 플랫폼은 해보고 확인하는 곳이다.

이 경계가 중요한 이유가 하나 더 있다. **과적합은 만질 손잡이가 있어야 생긴다.** 파라미터 공간을 규칙으로 좁히면 역할 1은 쉬워지지만 역할 2가 배울 신호가 사라진다. 위험한 조합도 통과시켜야 학습 데이터가 된다.

---

## 8. 이 서버가 하지 않는 것

| 하지 않는 것 | 이유 |
| --- | --- |
| DB 접근 | 무상태. 요청 본문에 필요한 데이터가 실려 온다 |
| 프론트 직접 호출 응대 | 프론트는 Spring만 부른다. CORS 설정을 두지 않는다 |
| 백테스트 실행 | 백테스트 엔진 담당 |
| 투자 판단 | 사용자 문장을 옮길 뿐, 전략의 좋고 나쁨을 정하지 않는다 |
| 자체 모델 학습 (역할 1) | 공개 LLM을 게이트웨이 경유로 호출 |

---

## 9. 기술 선택

| 항목 | 선택 | 근거 |
| --- | --- | --- |
| 언어 / 프레임워크 | Python 3.11 + FastAPI | Pydantic v2로 DSL 스펙을 그대로 타입으로 표현 |
| 스키마 정의 | Pydantic 모델 1개 파일 | 스펙 교체 시 수정 대상을 한 곳으로 묶는다 |
| LLM 호출 | `openai` SDK + SSAFY GMS 게이트웨이 | 공급자 교체가 `LLM_BASE_URL` 변경으로 끝난다 |
| LangChain | **쓰지 않는다** | 재시도 정책·프롬프트 조립·검증을 이미 직접 통제하기로 정했다. 넣으면 그쪽 방식으로 다시 설계해야 하고 코드는 줄지 않는다 |
| 프롬프트 | `.txt` 파일로 분리 | 프롬프트 수정에 코드 배포가 딸리지 않는다 |

---

## 10. 이 프로젝트에서 보여주고 싶은 것

> **"LLM으로 JSON을 만들었다"가 아니라, LLM 출력을 신뢰할 수 없는 입력으로 취급하고 스키마 검증·재시도·오류 계약으로 감싸 백엔드가 안전하게 소비할 수 있는 서비스로 만들었다.**

핵심 지표로 삼을 것:

- 골든 케이스 변환 정확도
- 첫 시도 성공률 / 재시도 발생률 / 최종 실패율
- 평균 응답 시간과 토큰 사용량
- 스펙 교체 시 실제로 수정된 파일 수 (원칙대로면 `schema.py` + 프롬프트 `.txt`뿐)
