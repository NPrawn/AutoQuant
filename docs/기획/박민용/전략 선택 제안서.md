# 전략 선택 제안서

> 확정안이 아니라 논의용 기록이다. MVP 팩터 세트를 어떤 기준으로 고르고, 백테스트 없이 무엇을 검증할지에 대한 제안.

## 1. 팩터를 고르는 기준부터 바꾸자

`RSI가 유명하니까`, `MACD를 많이 쓰니까`가 기준이 되면 안 된다. 먼저 우리가 표현하고 싶은 시장 정보를 정의한다.

| 시장에 던지는 질문 | 팩터 축 |
| --- | --- |
| 지금 어느 방향으로 움직이고 있는가? | **Trend / Momentum** |
| 너무 한쪽으로 움직였는가? | **Reversion / Position** |
| 얼마나 위험하게 움직이는가? | **Volatility** |
| 이 움직임에 거래 참여가 붙어 있는가? | **Volume / Liquidity** |
| 시장 전체와 같이 움직이는가, 독립적으로 움직이는가? | **Market Relation** |

이렇게 보면 서로 역할이 꽤 명확하게 다르다. 그래서 앞에서 말한 5개를 조금 수정해 **MVP 5축을 이렇게 잡는 걸 추천한다.**

| 축 | MVP 대표 지표 | 의미 |
| --- | --- | --- |
| Trend | **20일 수익률** 또는 MA20 기울기 | 방향/추세 |
| Reversion | **RSI(14)** | 과도한 상승·하락 |
| Volatility | **20일 실현변동성** | 위험 |
| Activity | **상대 거래량** | 시장 참여 |
| Market Relation | **BTC/시장과 30일 상관계수** | 시장 동조성 |

중요한 건 **처음부터 MACD, ROC, EMA, ADX, RSI, Stochastic… 30개를 넣지 않는 것**이다.

연구에서도 암호화폐 팩터는 상당히 많이 발견됐지만 서로 중복되는 문제가 있고, 2026년 연구에서는 시장 팩터 외에 소수의 팩터만으로 많은 효과가 설명되며 특히 유동성 관련 특성이 중요하게 선택된다는 결과가 나왔다. (ScienceDirect) 기존 연구에서도 모멘텀이 암호화폐 횡단면에서 중요한 축으로 보고됐고, (NBER) 암호화폐 수익률에는 fat tail과 volatility clustering이 뚜렷하게 존재한다. 따라서 변동성을 별도 축으로 두는 것도 근거가 있다. (ScienceDirect)

즉 **논문은 "정답 팩터"를 가져오는 용도가 아니라, 우리가 선정한 시장 특성 축에 근거가 있는지 확인하는 용도**로 쓴다.

---

## 2. 그러면 백테스트 없이 뭘 검증하느냐

여기서부터가 핵심이다. 팩터 하나하나에 대해 다음 **5단계 검증**을 한다.

### 의미대로 움직이는가 — Semantic Test

인위적인 가격 데이터를 만들어서 확인한다.

```
CASE A
가격:
100 → 102 → 104 → 106 → 108 → 110
→ Trend ↑
→ RSI ↑
→ Volatility 낮음
```

```
CASE B
가격:
100 → 80 → 120 → 70 → 130 → 90
→ Trend 애매
→ Volatility 매우 높음
```

```
CASE C
가격 일정
거래량:
100 → 100 → 100 → 1000
→ Relative Volume만 급증
```

이런 식으로 **팩터가 우리가 정의한 의미대로 반응하는지** 테스트한다. 그냥 unit test로 자동화할 수도 있다. 가상 시장을 만드는 이 프로젝트에는 특히 중요하다.

---

## 3. 30개 코인을 실제로 구분할 수 있는가 — Cross-sectional Dispersion

랭킹 서비스를 만들 거면 특히 중요하다. 어떤 날짜에

```
BTC   Trend = 0.051
ETH         = 0.052
SOL         = 0.051
XRP         = 0.052
...
```

이렇게 30개가 거의 같다면 **랭킹 팩터로 의미가 없다.** 반대로

```
BTC   +12%
ETH    +3%
SOL   +25%
XRP    -8%
LINK   +7%
...
```

처럼 차이가 나야 순위를 만들 수 있다. 따라서 날짜별로

```
Factor IQR
Factor Standard Deviation
Factor Min/Max
Unique Rank
```

를 본다. 예를 들어 20D Momentum:

```
2025-01-01 IQR = 0.08
2025-01-02 IQR = 0.11
2025-01-03 IQR = 0.02
...
```

여기서는 미래 수익률을 전혀 안 본다.

> **"이 지표가 30개 코인을 실제로 구별해주는가?"**

만 본다.

---

## 4. 다른 팩터와 중복되지 않는가

이게 굉장히 중요하다. 예를 들어 후보가

```
20D Return
ROC20
Price / MA20
MA20 Slope
Relative Strength
```

이면 이름은 다르지만 사실 대부분 **최근 상승한 코인**을 찾고 있을 수 있다.

그러면 날짜별 30개 코인의 순위를 가지고 Spearman correlation을 구한다.

|  | Return20 | ROC20 | MA Ratio | Volatility | Volume |
| --- | --- | --- | --- | --- | --- |
| Return20 | 1 | **0.99** | **0.88** | 0.17 | 0.21 |
| ROC20 |  | 1 | **0.87** | 0.15 | 0.20 |
| MA Ratio |  |  | 1 | 0.20 | 0.23 |
| Volatility |  |  |  | 1 | 0.31 |
| Volume |  |  |  |  | 1 |

그러면

```
Return20
ROC20
→ 사실상 같은 축
```

이라고 판단할 수 있다. 둘 중 **계산이 단순하고 사용자에게 설명하기 쉬운 Return20 하나만 남긴다.**

`|Spearman ρ| > 0.8` 정도가 지속적으로 나오면 MVP에서는 중복 여부를 의심한다. 이 0.8은 금융학의 절대 기준이 아니라 **서비스 설계를 위한 engineering heuristic**이다.

---

## 5. 파라미터 하나에 너무 의존하지 않는가

Momentum을 채택한다고 해보자.

```
Momentum 14D
Momentum 20D
Momentum 30D
```

를 각각 계산하고 30개 코인의 순위를 비교한다. 만약

```
Rank Corr
14D vs 20D = 0.82
20D vs 30D = 0.77
14D vs 30D = 0.66
```

라면 괜찮다. 기간이 조금 달라져도 대충 같은 시장 정보를 표현한다는 뜻이다. 반대로

```
19D vs 20D = 0.10
20D vs 21D = -0.15
```

처럼 결과가 완전히 바뀐다면 기본 팩터로 삼기 애매하다. 이것도 **수익성 검증이 아니다.** 지표 자체의 **측정 안정성**을 본다.

---

## 6. 극단값 하나 때문에 랭킹이 깨지지 않는가

코인에서는 특히 필요하다.

```
BTC      +5%
ETH      +8%
SOL     +12%
XRP      +3%
DOGE   +480%
```

DOGE 같은 극단값 하나 때문에 `min-max normalization`을 하면 나머지 29개 점수가 전부 비슷해질 수 있다. 그래서

```
Raw
↓
Winsorize
↓
Rank / Percentile
```

등을 적용했을 때 결과를 비교해야 한다.

```
Raw Rank vs Winsorized Rank
Spearman = 0.97
```

이면 안정적이고,

```
Spearman = 0.45
```

이면 극단값에 지나치게 민감하다는 신호다. 이건 나중에 **Synthetic Market에서 폭등/폭락을 생성할 것이기 때문에 특히 중요하다.**

---

## 7. 시장 상황이 달라질 때 의미 있게 반응하는가

이것도 수익률 백테스트와 다르다. 실제 데이터를 다음처럼 **현재 상태 기준으로** 나눈다.

```
상승 추세
하락 추세
고변동성
저변동성
고거래량
저거래량
```

그리고 팩터 분포를 본다. 고변동성 구간이면

```
20D Realized Volatility
평상시  0.04
고변동  0.13
```

처럼 명확히 반응해야 한다. 상승장이면 Trend 팩터가 전체적으로 양수 방향으로 이동해야 하고.

> **"우리가 상승장이라고 정의한 상황에서 Trend가 상승장이라고 읽는가?"**

를 확인한다. 미래 수익률과 관계가 있는지는 아직 안 본다.

## 9. 랭킹형인지 신호형인지도 여기서 판단 가능하다

팩터가 어떤 형태의 정보를 주는지를 본다.

**Return20**

```
BTC  +5%
ETH +12%
SOL +30%
```

본질적으로 연속값이고 종목 간 비교가 자연스럽다. → **Ranking에 매우 적합**

**RSI**

```
BTC 29
ETH 45
SOL 73
```

랭킹도 가능하지만 `RSI < 30`, `RSI > 70`이라는 해석 가능한 영역이 존재한다. → **Signal에 적합**

**Volatility**

```
BTC  3%
ETH  5%
SOL  9%
```

낮은 변동성 순위 등 **Ranking에 적합**. 동시에 `Volatility > 10% → 거래 금지`처럼 **Risk Signal에도 적합**.

**Relative Volume**

```
BTC  0.8
ETH  1.1
SOL  3.2
```

Ranking도 가능하고 `Relative Volume > 2`처럼 Signal도 가능하다.

즉 애초부터

```
RSI = 신호
Momentum = 랭킹
```

으로 하드코딩할 필요가 없다. **팩터는 값만 제공하고, 사용자가 그 값을 어떻게 소비하는지를 분리하는 게 엔진 설계상 더 좋다.**

백테스트를 만들 필요가 없다.

```
30종목 OHLCV
      ↓
────────────────────
① Trend
   Return20
② Reversion
   RSI14
③ Risk
   Realized Vol20
④ Activity
   Relative Volume20
⑤ Market Relation
   BTC Corr30
────────────────────
      ↓
Factor Validation

2. 데이터 결측/coverage
3. Cross-sectional dispersion
4. Factor correlation

```

여기까지 통과하면

> **"이 5개 팩터는 수익성이 입증됐다."**

가 아니라

> **"이 5개 팩터는 서로 다른 시장 특성을 안정적으로 표현하므로, 사용자가 전략을 구성하기 위한 MVP 기본 요소로 적합하다."**

라고 결론 내린다. 이 차이가 중요하다.

## 11. 우선 검증할 5개

**Trend → `20D Return`**
가장 단순하고 설명하기 쉽다. Momentum 연구에서도 암호화폐의 주요 특성으로 반복해서 등장한다. (NBER)

**Reversion → `RSI14`**
과도한 가격 이동이라는, Trend와 다른 개념을 제공한다. 단기 암호화폐 시장에서 reversal 현상도 관찰돼 왔지만 유동성에 따라 결과가 달라진다는 연구가 있어, 독립적인 전략 축으로 제공할 이유는 충분하되 "수익나는 지표"로 표현하면 안 된다. (ScienceDirect)

**Risk → `20D Realized Volatility`**
암호화폐의 volatility clustering은 매우 강하게 관찰되는 특성이라 반드시 하나는 필요하다. (ScienceDirect)

**Activity → `Relative Dollar Volume`**
가능하면 단순 코인 수량 Volume보다 `가격 × 거래량`을 기반으로 하는 게 비교에 낫다. 유동성·거래 가능성이 암호화폐 팩터 연구에서 중요한 축으로 반복 등장한다. (ScienceDirect)

**Market Relation → `BTC Correlation` 또는 `Market Correlation`**
개별 코인의 절대 방향과 별도로 **시장 전체와 얼마나 동조하는가**라는 정보를 준다. 앞의 네 개와 가장 다른 축이기도 하다.

따라서 지금 단계에서는 **"좋은 팩터를 찾는다"보다 "서로 다른 시장 상태를 표현하는 최소 센서 세트를 만든다"**고 생각하면 훨씬 명확해진다.

이 검증을 실제로 구현한다면 `팩터명 / 공식 / 기대 동작 / 검증 메트릭 / 채택 기준`까지 정해서 **팀에서 바로 개발 가능한 팩터 검증 명세**로 만들 수 있다. 그걸 먼저 정하면 이후 랭킹/신호형 설계도 자연스럽게 따라온다.
