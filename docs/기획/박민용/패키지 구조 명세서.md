## 2. 계층 규칙

```
api  →  services  →  core
```

**의존은 안쪽으로만 흐른다.** `core`는 `services`와 `api`를 모른다. 그래서 스키마 테스트가 네트워크 없이 돈다.

| 계층 | 책임 | 하지 않는 것 |
| --- | --- | --- |
| `api` | 요청·응답 변환, 의존성 주입, 예외의 HTTP 변환 | 비즈니스 로직, `try/except`로 상태 코드 만들기 |
| `services` | 오케스트레이션, 프롬프트 조립, 검증, 외부 통신 | 검증 규칙 정의 |
| `core` | DSL 정의, 설정, 예외 타입, 로깅 | 외부 호출 |
| `prompts` | 프롬프트 문구 | 코드가 아니다 |

## 3. 파일별 책임

### `app/main.py`

FastAPI 앱을 만들고 라우터와 예외 핸들러를 등록한다. 기동 시 설정 검증을 여기서 한다. **CORS는 두지 않는다** — 이 서버는 Spring만 호출한다. 비즈니스 로직은 한 줄도 두지 않는다.

### `app/api/v1/strategy.py`

`POST /api/v1/ai/strategies/translate` 하나를 정의한다. 요청 본문을 `translator`에 넘기고 결과를 응답 모델로 감싼다. LLM이나 검증을 직접 호출하지 않는다. **라우터는 얇게 유지한다.**

### `app/api/v1/health.py`

`GET /health`(프로세스 생존)와 `GET /health/ready`(설정·프롬프트 로드 가능 여부). **LLM API를 호출하지 않는다.** 과금 요인이 헬스체크에 붙으면 안 된다.

### `app/api/deps.py`

라우터가 쓸 의존성 주입 함수를 모은다. 테스트에서 이 의존성만 교체하면 가짜 LLM으로 API 테스트가 돌아간다.

### `app/api/error_handlers.py`

도메인 예외를 HTTP 응답으로 바꾼다. `DomainError`가 `status_code`와 `code`를 속성으로 들고 있어 핸들러가 예외 종류를 분기하지 않는다. 예외 타입을 늘려도 이 파일은 그대로다.

> 계획서는 핸들러를 `main.py`에 두라고 적었지만, 실제 구현은 이 파일로 뺐다. `main.py`를 앱 조립과 미들웨어만 남기려고 나눴다.

### `app/core/schema.py` — 이 프로젝트에서 가장 중요한 파일

**DSL 스펙의 단일 정의처.** `Strategy`와 하위 모델, 열거형, 범위 제약, 조합 제약을 전부 담는다. API 요청·응답 모델도 같은 파일에 둔다 — 응답이 `Strategy`를 감싸는 형태라 분리하면 스펙이 두 군데로 흩어진다.

**스펙이 교체될 때 수정하는 파일은 원칙적으로 여기 하나다.**

### `app/core/config.py`

환경변수를 읽어 설정 객체 하나를 만든다. `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_TIMEOUT_SECONDS`, `MAX_RETRIES`(기본 2), `LOG_LEVEL`.

**필수값이 없으면 앱 기동 단계에서 죽는다** — 첫 요청에서 죽으면 안 된다. 키 값이 로그·응답 어디에도 나가지 않도록 표현(`repr`)을 막는다.

### `app/core/errors.py`

도메인 예외와 오류 코드를 정의한다. `LLMTimeoutError`, `LLMUpstreamError`, `DSLValidationError`, `PromptTooLongError`. 각 예외가 HTTP 상태 코드와 오류 코드 문자열을 갖는다.

### `app/core/logging.py`

구조화 로깅. 요청 ID를 붙이고 LLM 호출마다 시도 횟수·소요 시간·토큰 수·성공 여부를 남긴다. **사용자 입력 원문은 남기고 API 키는 남기지 않는다.**

### `app/services/translator.py`

역할 1의 핵심 흐름을 지휘한다. 프롬프트 구성 → LLM 호출 → 파싱 → 검증 → 실패 시 재시도. 재시도 횟수와 종료 조건을 여기서 판단한다. **프롬프트 문구를 직접 만들지 않고, HTTP를 직접 치지 않는다.**

### `app/services/llm_client.py`

LLM 공급자와 통신하는 **유일한** 파일. 메시지 목록을 받아 텍스트를 돌려준다. 타임아웃과 HTTP 오류를 도메인 예외로 번역한다. 공급자를 바꾸면 이 파일만 고친다. 테스트에서는 같은 시그니처의 가짜 구현으로 대체한다.

### `app/services/prompt_builder.py`

`app/prompts/*.txt`를 읽어 자리표시자를 채운다. 시스템 프롬프트에 **`schema.py`에서 생성한 JSON Schema를 끼워 넣어** 스펙이 바뀌면 프롬프트도 따라오게 한다. 프롬프트 파일은 기동 시 한 번 읽어 캐시한다.

### `app/services/validator.py`

LLM 원문 텍스트를 JSON으로 파싱하고 `Strategy` 모델로 검증한다. 코드 블록 표시를 벗겨내는 정도의 관용은 여기서만 처리한다. 검증 실패 시 **필드 경로 + 무엇이 잘못됐는지** 형태로 오류 문자열을 만든다 — 이 문자열 품질이 재시도 성공률을 좌우한다. **검증 규칙 자체는 정의하지 않고 `schema.py`에 위임한다.**

### `app/prompts/*.txt`

| 파일 | 내용 |
| --- | --- |
| `system.txt` | 역할 지시, DSL 스펙(자리표시자로 주입), 출력 형식 규칙, 기본값 정책 |
| `user.txt` | 사용자 입력을 감싸는 최소 템플릿 |
| `retry.txt` | 직전 출력과 검증 오류를 제시하고 고쳐서 다시 내라는 지시 |

사용자 입력 안에 지시문처럼 보이는 문장이 있어도 시스템 규칙을 덮지 못하도록, **입력은 구분된 블록 안에 넣는다.**

## 4. 이 구조가 지키려는 것

**① DSL 필드명은 `schema.py` 밖으로 새지 않는다.**
프롬프트에 들어갈 스펙 문구조차 `schema.py`가 만든 JSON Schema를 주입해 만든다. 명세가 교체될 때 수정 대상이 `schema.py` + 프롬프트 `.txt`로 끝나야 한다. 그 밖의 파일이 수정되면 어디선가 필드명이 샌 것이다.

**② 환경변수를 읽는 파일은 `config.py` 하나다.**
다른 파일은 `os.environ`을 직접 만지지 않고 설정 객체를 주입받는다.

**③ HTTP 변환은 `error_handlers.py` 한 곳에서만 한다.**
라우터에서 상태 코드를 만들지 않는다.

**④ 외부 의존은 인터페이스 뒤에 숨긴다.**
`llm_client` 하나만 네트워크를 안다. 그래서 기본 테스트 스위트가 네트워크 없이 돈다.
