# 백엔드 확장 가상 이슈 목록

실제 외부 이슈를 생성하지 않고 확장 작업을 GitHub 이슈처럼 관리한다. 실행·커밋·푸시·기록 절차의 정본은 [Git 작업 컨벤션 5절](git-convention.md#5-백엔드-확장-작업의-가상-이슈-운영)이다. 설계 범위는 [확장계획](../AutoQuant_백엔드_확장계획.md), 완료 결과는 [작업·검증 기록](backend-extension-log.md)에서 확인한다.

각 커밋 단위는 관련 코드·테스트·설정 변경을 함께 검증할 수 있는 범위로 잡는다. 이 문서의 향후 커밋 이름은 작업 범위를 설명하는 계획이며 구현 사실이 아니다. 실험에서 확인한 원인에 따라 구체적인 변경은 조정한다.

## AQ-BE-001 — 실제 DB·Redis 통합 테스트 기준선 복원

목적: 환경 조건 때문에 실행되지 않던 실제 연동 테스트를 활성화하고, 드러난 테스트 구성·데이터 문제를 해결한다.

현재 확인한 내용: 최초 전체 빌드는 912개 중 895개 통과·17개 건너뜀이다. 실제 DB·Redis를 연결한 대상 5개 클래스는 파라미터 사례를 포함해 43개 중 38개 통과·5개 실패였다. 캔들 클래스는 사용자 fixture 수정 후 별도 실행에서 6개 모두 통과했다. 차트 클래스의 Bean 등록은 수정됐고 fixture 수정·실행은 대기 중이다.

커밋 단위:

- [ ] `fix: 캔들 통합 테스트를 초기 종목 데이터와 분리` — 사용자 변경과 6개 통과 증빙 확인 완료, 로컬 커밋 대기.
- [ ] `fix: 차트 종목 통합 테스트의 수집 대상 조건 반영` — Bean 등록, 초기 데이터와 구별되는 종목, 수집 대상 fixture를 함께 검증한다.
- [ ] `docs: 실제 DB·Redis 통합 테스트 실행 절차 정리` — API README의 실행·검증 절차를 현재 방식에 맞춘다.
- [ ] 작업 커밋 푸시 후 이슈 완료 기록 커밋·푸시

완료 조건:

- [ ] 차트 테스트 1개와 캔들 테스트 6개가 각각 실패·오류·건너뜀 없이 통과한다.
- [ ] 대상 5개 클래스의 43개 테스트가 함께 통과한다.
- [ ] 세 테스트 환경변수를 적용한 `bash ./gradlew build --rerun-tasks`가 성공하고 전체 테스트의 실행·실패·오류·건너뜀 수를 확인한다.
- [ ] 실패·수정 후 보고서와 코드 변경을 보관하고, 이슈의 작업 커밋들을 푸시했다.

커밋 단위:

- [ ] `chore: 백테스트 실험 환경과 자원 조건 정의` — 서비스 구성·이미지·CPU/RAM·DB 풀·Worker 수를 기록하고 실행 경로를 분리한다.
- [ ] `test: 고정 데이터와 요청으로 백테스트 기준선 재현` — 종목·전략·기간·캔들·요청 수가 정해진 재현 절차 또는 스크립트를 준비한다.
- [ ] 작업 커밋 푸시 후 기준선 결과 기록 커밋·푸시

## AQ-BE-005 — Worker 중단·재전달 장애 검증과 복구 개선

목적: 기존 Outbox·중복 시작 방어를 출발점으로, 실행 중인 Worker가 중단될 때의 결과 정합성과 복구를 검증한다.

커밋 단위:

- [ ] `test: Worker 중단과 재전달 장애 시나리오 재현` — 시작 직후·RUNNING 중·결과 저장 중·중복 전달을 구별한다.
- [ ] 발견한 복구 문제의 수정과 해당 회귀 테스트 — Lease·실행 소유권·타임아웃 등은 관측한 원인에 맞춰 선택하고 커밋 제목을 확정한다.
- [ ] 작업 커밋 푸시 후 복구·정합성 검증 기록 커밋·푸시

완료 조건: 복구 시간, 완료율, 재시도·중복 실행·중복 저장 수, 최종 DB 상태를 수집하고 최소 1개의 신규 장애 시나리오를 자동 재현한다. 확인된 문제가 없으면 무리한 변경 대신 한계와 관측 결과를 기록한다.

## AQ-BE-006 — PostgreSQL 읽기 병목 분석과 개선

목적: 실제 비용이 큰 조회 1~2개를 선정하고 실행계획에 근거해 개선한다.

커밋 단위:

- [ ] `test: 읽기 쿼리의 실행계획과 반복 측정 재현` — 데이터 규모·분포·인덱스·캐시 조건과 SQL을 고정한다.
- [ ] 확인된 원인에 맞는 쿼리·인덱스 개선과 정합성 검증 — 필요한 스키마 변경은 새 Flyway로 추가한다.
- [ ] 작업 커밋 푸시 후 쿼리 전후 비교 기록 커밋·푸시

완료 조건: 변경 전후 `EXPLAIN (ANALYZE, BUFFERS)`, median/p95, 결과 정합성, 쓰기 비용·인덱스 공간 영향을 남긴다. 개선되지 않은 실험과 미채택 이유도 결과로 인정한다.

목적: 로컬에서만 실행하던 DB·메시지·복구 검증을 CI에서도 반복하고 실패 시 배포를 막는다.

커밋 단위:

- [ ] `test: 실제 PostgreSQL RabbitMQ 통합 검증 환경 자동화` — Testcontainers 또는 격리 Compose를 선택하고 외부 Upbit·AI는 고정 대역을 사용한다.
- [ ] `ci: 통합 검증 누락과 실패 시 배포 차단` — Jenkins의 테스트 실행·건너뜀·실패 전파를 확인한다.
- [ ] 작업 커밋 푸시 후 CI 실행 증빙 기록 커밋·푸시

완료 조건: Outbox·중복 소비·결과 저장 실패·모의투자 재선정 복구 시나리오의 실행 결과와 의도적인 실패 시 배포 차단 증빙을 확보한다. 로컬 통과만으로 CI 완료를 선언하지 않는다.

## AQ-BE-009 — 검증된 사례를 포트폴리오 자료로 편집
