# S15P21A107 작업 컨벤션

> 적용 프로젝트: `S15P21A107` 암호화폐 모의투자·전략 플랫폼
> 협업 도구: GitLab · Jira

## 1. Jira 작업 컨벤션

### 1.1 작업 제목

Jira 작업 제목은 다음 형식을 사용한다.

~~~text
[영역] 대상과 작업 내용
~~~

영역은 `FE`, `BE`, `INGEST`, `AI`, `INFRA`, `DOCS`, `COMMON` 중 하나를 사용한다.

- `FE`: Frontend 화면, 차트, 전략 구성 UI
- `BE`: API, 전략, 백테스트, 모의투자 도메인
- `INGEST`: Upbit 데이터 수집·적재·보정
- `AI`: 전략 DSL 변환 및 AI 기능
- `INFRA`: 인프라 및 운영 설정
- `DOCS`: 특정 기술 영역에 속하지 않는 문서
- `COMMON`: 여러 영역에서 함께 사용하는 공통 설정·정책

예시:

~~~text
[BE] 백테스트·모의투자 ERD 상세 설계
[INGEST] Upbit 1시간봉 수집 및 저장
[AI] 자연어 전략 DSL 변환 검증
[INFRA] Kafka·Redis·PostgreSQL 개발 환경 구성
[DOCS] 프로젝트 작업 컨벤션 작성
~~~

작성 규칙:

- Jira 프로젝트 키는 제목에 작성하지 않는다.
- 제목만 보고 대상과 작업 결과를 알 수 있게 작성한다.
- 하나의 Jira 작업에는 하나의 결과물을 명시한다.
- 전체 작업은 Story 또는 Task로 만들고 세부 작업은 Sub-task로 분리한다.
- 독립된 결과물은 별도 Jira 작업으로 분리한다.

### 1.2 작업 내용

Jira 설명은 다음 최소 구조를 사용한다.

~~~markdown
## 목적

작업의 목적을 한두 문장으로 작성합니다.

## 작업 내용

- 수행할 작업을 작성합니다.
- 필요한 경우 변경 대상이나 범위를 함께 작성합니다.

## 완료 조건

- [ ] 작업 결과물이 작성되어 있다.
- [ ] 관련 문서 또는 명세가 반영되어 있다.
~~~

제외 범위, 참고 자료, 의존 작업은 필요한 경우에만 추가한다. Jira 이슈 키는 원본 대문자와 하이픈을 유지한다.

## 2. 브랜치명 컨벤션

모든 작업 브랜치는 다음 형식을 사용한다.

~~~text
feat/<jira-key>
~~~

예시: `feat/S15P21A107-33`

작성 규칙:

- 브랜치 접두사는 항상 `feat`를 사용한다.
- 브랜치명에 Jira 이슈 키를 반드시 포함한다.
- 작업 설명, 영역, 별도 slug는 브랜치명에 작성하지 않는다.
- 하나의 작업 브랜치는 하나의 Jira 작업만 처리한다.

## 3. 커밋 메시지 컨벤션

커밋 메시지는 다음 형식을 사용한다.

~~~text
<type>: <한국어 작업 내용>
~~~

예시:

~~~text
feat: 백테스트 실행 API 구현
fix: 빈 캔들 구간 처리 오류 수정
refactor: 체결 계산 로직 분리
docs: 백테스트 모의투자 ERD 상세 설계
~~~

작성 규칙:

- Type은 영문 소문자로 작성한다.
- 작업 내용은 한국어로 작성한다.
- Jira 키는 커밋 메시지에 직접 작성하지 않는다.
- 제목 끝에 마침표를 붙이지 않는다.
- 하나의 커밋에는 하나의 논리적인 변경만 담는다.
- `수정`, `작업`, `완료`처럼 의미가 불명확한 표현만 사용하지 않는다.

Git Hook을 사용하는 경우 현재 브랜치명에서 Jira 키를 추출해 커밋 메시지 끝에 자동으로 추가할 수 있다. Hook이 적용되지 않은 환경에서도 Jira 키를 수동으로 추가하지 않으며, Jira 연결은 브랜치명과 MR 제목으로 관리한다.

## 4. Merge Request 컨벤션

### 4.1 MR 제목

~~~text
[<PART>] <type>: <한국어 작업 내용>-<jira-key>
~~~

예시:

~~~text
[BE] feat: 백테스트 실행 API 구현-S15P21A107-40
[BE] docs: 백테스트 모의투자 ERD 상세 설계-S15P21A107-33
[INGEST] feat: Upbit 캔들 수집 구현-S15P21A107-41
[AI] feat: 전략 DSL 변환 검증 구현-S15P21A107-42
[INFRA] chore: 로컬 Kafka 환경 구성-S15P21A107-43
[DOCS] docs: 프로젝트 작업 컨벤션 작성-S15P21A107-44
~~~

작성 규칙:

- 영역은 대문자로 작성한다.
- Type은 영문 소문자로 작성한다.
- 작업 설명은 한국어로 작성한다.
- Jira 키는 제목 맨 끝에 직접 작성한다.
- 브랜치의 Jira 키와 MR 제목의 Jira 키는 일치해야 한다.
- 작업 설명과 Jira 키는 하이픈으로 구분한다.
- 제목 끝에 마침표를 붙이지 않는다.

### 4.2 MR 본문

MR 본문은 다음 최소 구조를 사용한다.

~~~markdown
## Jira

- [S15P21A107-00](https://ssafy.atlassian.net/browse/S15P21A107-00)

## 변경 사항

- 변경 내용을 작성합니다.

## 확인 사항

- [ ] 변경 내용을 확인했습니다.
- [ ] 관련 문서 또는 명세를 반영했습니다.
~~~

MR의 Target branch는 `develop`으로 설정한다. Reviewer를 지정하고, 필요한 경우 관련 Jira 작업이나 MR을 변경 사항에 함께 작성한다.
