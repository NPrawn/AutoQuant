# ADR-0013. 대회 전략의 팩터 기간은 대회 데이터의 워밍업 안으로 제한한다

- 상태: 채택
- 날짜: 2026-09-14 (2026-09-16 워밍업 30주로 개정)
- 관련: ADR-0005, ADR-0011, ADR-0016

## 배경

- 엔진은 평가를 시작하기 전에 `팩터 최대 기간 + 1`개의 캔들을 요구한다 (`BacktestWarmupCandleCountResolver`). 캔들이 부족한 종목은 빠지고, 모든 종목이 부족하면 백테스트가 실패한다.
- 연습 백테스트는 8년치 실제 데이터를 쓰기 때문에 일봉 50·120·200일 같은 긴 기간도 계산된다.
- 처음에는 워밍업을 5주로 두고 참가자가 상한(일봉 34)에 맞추게 했다. 실제로 써 보니 일봉 60·120·200일을 쓰는 보통의 전략이 대회에 아예 들어오지 못했다. 연습에서 되던 전략이 제출만 막히는 것은 참가자에게 설명하기 어렵다.

## 결정

- 대회는 제공한 데이터 안에서만 한다. 워밍업은 **30주**로 한다. 일봉 200일 전략까지 받기 위한 길이다.
- timeframe별 팩터 기간 상한은 `워밍업 캔들 수 − 1`이다.

  | timeframe | 상한 | 달력 기준 |
  |---|---|---|
  | 1H | 5,039 | 약 210일 |
  | 4H | 1,259 | 약 210일 |
  | 1D | 209 | 약 210일 |

- 상한은 회차의 `warmup_weeks`에서 계산한다. 회차마다 다른 길이를 쓸 수 있고 코드는 바뀌지 않는다.
- 상한은 대회 공지와 상세 화면에 적고, 참가자가 이 안으로 전략을 조정한다.
- 상한을 넘는 전략은 제출할 때 막는다 (`CONTEST-400-001`).

## 검토한 대안

- **워밍업 5주 유지 (2026-09-14 결정).** 데이터가 18주로 짧아 생성·적재가 가볍다. 하지만 일봉 35일 이상을 쓰는 전략을 모두 막아 대회 참가 폭이 지나치게 좁았다. 2026-09-16에 뒤집었다.
- **상한을 넘는 전략도 받고 백테스트에서 실패시킨다.** 팩터 값이 만들어지지 않아 매수 신호가 나오지 않고, 현금으로 끝나 평균 투자 비중 미달로 실격된다. 제출은 되지만 결과가 0점이라 더 나쁘다.
- **워밍업 구간은 4시간봉·일봉만 싣는다.** 마이그레이션이 32MB에서 20MB로 줄지만, 1시간봉 상한(5,039)이 실제로 들어 있지 않은 데이터를 가리키게 된다. 상한과 데이터가 어긋나는 쪽이 파일 크기보다 위험하다.

## 결과

- 워밍업 30주 + 평가 13주 = 43주 데이터다. 1회차는 V26이 같은 회차 ID의 데이터를 지우고 다시 넣었다 (ADR-0016).
- 캔들은 1시간봉 288,960행, 4시간봉 72,240행, 일봉 12,040행으로 373,240행이다. 마이그레이션은 32MB이고 빈 DB 적용에 14.2초 걸렸다.
- 2026-09-16 로컬 확인: 일봉 200일과 209일 전략 제출은 통과, 210일은 `CONTEST-400-001`이다.
- 평가는 13주 그대로다. 채점 규칙(ADR-0002, ADR-0003)과 장세 목표는 바뀌지 않았다.
- 생성기 기본값도 30주로 올렸다. 플래그 없이 만든 데이터가 회차 설정과 어긋나지 않게 한다.
- 워밍업 주 수를 바꾸면 상한도 같이 바뀐다. 상한은 회차 응답과 대회 데이터 manifest에 기록한다.
