# ADR-0014. 대회 데이터셋은 contest 스키마에 두고, 대회 백테스트는 데이터셋 ID로 캔들과 종목을 고른다

- 상태: 채택
- 날짜: 2026-09-15
- 관련: ADR-0005, ADR-0006, ADR-0007, ADR-0010, ADR-0012, ADR-0013

## 배경

- 엔진은 캔들을 `HistoricalCandleProvider` 하나(`market_data.minute_candle`)에서, 종목 후보를 `BacktestUniverseResolver`(그 기간에 거래지원 중인 업비트 KRW 종목 전체)에서 고른다. 백테스트 한 건이 어떤 데이터를 써야 하는지 알 방법이 없다.
- 대회 데이터 4벌(일반장·상승장·하락장·횡보장)은 종목과 가상 날짜(2030년)가 같다. 한 캔들 테이블에 함께 둘 수 없다.
- 로컬 대회(ADR-0012 결과)는 전용 DB에서 `minute_candle`을 데이터셋마다 비우고 바꿔 넣었다. 여러 회차나 참가자를 동시에 채점하면 쓸 수 없다.
- 대회 데이터는 운영 배치 없이 로컬에서 생성기로 만들어 넣는다(2026-09-15 범위 정리). ADR-0006은 테이블 구조를 별도 ADR로 확정하기로 했다.
- 엔진은 보유 종목의 빈 시간을 처리하지 못한다(ADR-0012 결과).

## 결정

1. **저장.** `contest` 스키마에 데이터셋 테이블을 둔다.
   - `contest.market_dataset`: 데이터셋 한 벌. 회차, 종류, 평가 기간, 원본 구간, 시드, 뽑은 주, 평가 구간 균등 보유 수익률을 담는다.
   - `contest.market_dataset_asset`: 데이터셋 종목.
   - `contest.market_candle`: 데이터셋별 1시간봉·4시간봉·일봉. 값 열은 `market_data.minute_candle`과 같다.
2. **연결.** `trading.backtest_run`에 NULL 허용 `contest_dataset_id`를 둔다. 비어 있으면 지금처럼 실제 캔들을 쓰고, 값이 있으면 그 데이터셋만 쓴다.
3. **경로.** `BacktestCandleWindowProvider`와 `BacktestUniverseResolver`가 백테스트의 데이터셋 ID를 보고 경로를 고른다. 데이터셋 조회는 trading 패키지의 인터페이스로 받고 contest 패키지가 구현한다. trading은 contest를 직접 참조하지 않는다. 모의투자 경로는 바꾸지 않는다.
4. **종목.** 대회 백테스트의 종목 후보는 데이터셋 종목이다. `reference.asset`의 거래지원 기간과 상태는 보지 않는다. 가상 날짜에 실제 거래지원 기간을 적용할 이유가 없다.
5. **빈 시간.** 대회 데이터는 생성할 때 거래 없는 시간을 직전 종가·거래량 0 봉으로 채운다. 실제 캔들 정책(ADR-0005)은 바꾸지 않는다.
6. **적재.** 로컬 도구가 생성기 출력을 `contest` 테이블에 직접 넣는다. ADR-0006의 적재 API는 운영 배치를 만들 때 다시 정한다.
7. **노출.** 대회 백테스트는 사용자 백테스트 목록에 나오지 않는다.

## 검토한 대안

- **데이터셋마다 `minute_candle`을 비우고 바꿔 넣는다(로컬 대회 방식).** 한 번에 한 벌만 올릴 수 있어 동시 채점이 안 되고, 운영 DB에서는 실제 캔들을 지운다.
- **대회 전용 DB를 따로 둔다.** 회원·전략·종목을 두 DB에 맞춰야 하고 운영할 DB가 늘어난다.
- **`minute_candle`에 데이터셋 ID 열을 더한다.** 실제 캔들의 기본 키, Go 수집기와 롤업 트리거, Redis 캐시 경로가 모두 바뀐다. 확정 분봉은 Go가 쓰는 계약이라 대회 때문에 건드리지 않는다.
- **`market_data_version` 문자열로 경로를 고른다.** 문자열 규칙이 계약이 되고, 데이터셋과의 무결성을 DB가 보장하지 못한다.
- **대회용 백테스트 테이블을 따로 둔다.** 실행·결과·체결·자산 추이 테이블과 조회 코드를 복제해야 한다.

## 결과

- Flyway 새 버전으로 `contest` 스키마와 `backtest_run.contest_dataset_id`를 추가한다.
- 엔진은 캔들을 `MinuteCandle` 엔티티로 받는데, 이 엔티티에는 보호된 기본 생성자만 있다. 대회 캔들을 엔진에 넘기려면 저장하지 않는 `MinuteCandle`을 만드는 방법을 더하거나 엔진용 캔들 타입을 둬야 한다. 변경이 작은 앞쪽을 먼저 시도한다.
- 저장 구조는 대회 데이터 조작 방식(ADR-0011, ADR-0012)과 독립이다. 조작 방식이 바뀌어도 테이블은 그대로다.
- 채점은 기존 백테스트 큐와 worker를 그대로 쓴다. 참가 수 × 4회만큼 몰리는 부하는 채점 작업에서 잰다.
