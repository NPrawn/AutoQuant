# ADR-0006. 파일 배치로 생성하고 contest 스키마에 적재한다

- 상태: 채택 (저장 테이블 상세는 미확정)
- 날짜: 2026-09-14
- 관련: ADR-0005, ADR-0007

## 배경

- AI 서버는 DB에 직접 연결하지 않는 무상태 서비스다 (루트 `CLAUDE.md` 모듈 경계).
- 엔진은 캔들을 `HistoricalCandleProvider.load(assetIds, timeframe, from, to)` 한 곳에서만 읽는다. 지금 구현은 `market_data.minute_candle`을 읽는 `JpaHistoricalCandleProvider` 하나다.
- 원본이 고정된 과거라 입력은 바뀌지 않고, 회차마다 바뀌는 건 시드와 평가 구간이다.
- 규모: 8년 전체를 변조하면 한 벌이 30종목 × (1시간봉 약 70,000 + 4시간봉 17,000 + 일봉 2,900), 최대 약 270만 행이다.

## 결정

1. **원본 내보내기 (한 번).** 백엔드 쪽에서 2018~2025 1시간봉을 CSV로 내보내고 sha256을 기록한다.
2. **생성 (회차마다).** Python CLI 생성기가 원본 파일과 시드를 받아 `candles.csv.gz`와 `manifest.json`을 만든다. 입력만으로 출력이 정해지는 순수 함수이고 표준 라이브러리만 쓴다.
   - `candles.csv` 열: `asset_id, interval_minutes, open_time, open_price, high_price, low_price, close_price, trade_volume, trade_amount`
   - `manifest.json`: 종류, 시드, 파라미터, 생성기 버전, 원본 sha256, 평가 구간, 간격별 행 수, 결과 sha256
3. **적재 (회차마다).** 데이터셋 행을 `LOADING`으로 만들고 COPY로 넣은 뒤, 행 수와 해시가 manifest와 맞으면 `READY`로 바꾸고 파일을 지운다.
4. **실행.** 대회 백테스트는 `HistoricalCandleProvider`의 대회용 구현이 데이터셋 ID로 `READY` 데이터만 읽는다. 엔진 본체는 고치지 않는다.

`last_event_time`은 생성하지 않는다. 엔진이 가격 외에 쓰는 값은 거래량과 거래대금뿐이다 (`Ta4jFactorCalculator`).

## 검토한 대안

- **AI 서버 API로 생성하고 Spring이 저장한다.** 모듈 경계는 지키지만 응답이 한 벌에 수백 MB다. 종목 단위로 나누면 30종목을 한꺼번에 봐야 하는 계산(장세의 공통 움직임, ADR-0009)이 꼬인다.
- **오프라인 배치가 DB를 직접 읽고 쓴다.** 생성기가 DB 접속 정보를 가져 모듈 경계를 어긴다. 저장 테이블과 provider는 어차피 필요해서 줄어드는 작업은 API 하나뿐이다.
- **저장하지 않고 백테스트마다 시드로 다시 만든다.** 1,284팀 × 4회 = 5,136번 생성하고, 생성기 코드가 바뀌면 지난 회차를 재현할 수 없다.
- **Parquet 파일.** pyarrow 의존성이 생기고 얻는 건 파일 크기뿐이다.

## 결과

- 백엔드에 요청할 것:
  - `contest` 스키마 migration
  - 대회용 provider와, 대회 실행이 데이터셋 ID로 provider를 고르는 경로 (지금은 provider가 `@Component` 하나라 고를 수 없다)
  - `MinuteCandle`은 public 생성자가 없는 JPA 엔티티라, 대회 캔들을 `MinuteCandle`로 바꾸는 팩토리
- 회차마다 배치를 한 번 돌려야 한다 (Jenkins job으로 자동화 가능). 채점용 데이터가 파일로 새지 않게 적재 후 지운다.
- 주간 회차면 1년에 약 1.4억 행이 쌓인다. 최근 N회차만 보관하고 지난 회차는 manifest로 다시 만든다. 삭제가 느려지면 데이터셋 ID 기준 파티션으로 바꾼다.
- 평가 구간이 8년 전체면 백테스트 한 번에 캔들 약 210만 개를 메모리에 올린다. 저장보다 엔진 부하가 먼저 한계라, 평가 구간은 ADR-0010에서 90일로 제한한다.
- 테이블 구조(`contest.market_dataset`, `contest.market_candle`)는 시뮬레이션(ADR-0007) 뒤에 별도 ADR로 확정한다.
