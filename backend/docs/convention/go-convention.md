# Go 컨벤션

Go 1.26, `backend/ingest` 파이프라인(Upbit 수집 → Kafka 발행 → 소비 → Redis/PostgreSQL 적재) 코드에 적용한다.

## 공통 원칙

- 지정되지 않은 라이브러리는 도입 전에 확인한다. 확정 의존성: `twmb/franz-go`, `redis/go-redis/v9`, `jackc/pgx/v5`, `gorilla/websocket`, `shopspring/decimal`.
- 표준 라이브러리로 충분한 일에 외부 의존성을 추가하지 않는다.
- 변경 후 `go build ./...`와 `go vet ./...`, 관련 테스트를 실행한다.

## 프로젝트 구조

- 바이너리 진입점은 `cmd/<바이너리명>/main.go` 하나씩 둔다. `main.go`는 설정 로드 → 의존성 조립 → 실행 → 그레이스풀 종료만 담당하고 비즈니스 로직을 두지 않는다.
- 실제 로직은 전부 `internal/` 아래 패키지에 둔다. `pkg/`는 모듈 밖에서 공유할 코드가 실제로 생기기 전에는 만들지 않는다.
- 패키지는 역할 단위로 나눈다: `upbit`(외부 API 클라이언트), `kafka`(토픽·메시지·프로듀서·컨슈머), `redis`(캐시 쓰기), `store`(DB 적재), `config`(설정).
- 토픽 이름, Redis 키 규칙, 메시지 구조체는 각 담당 패키지 한 곳에만 상수·타입으로 정의한다. 다른 패키지에서 문자열 리터럴로 중복 정의하지 않는다.

## 코드 스타일과 네이밍

- `gofmt`와 `goimports`를 통과하지 않은 코드는 커밋하지 않는다.
- 패키지명은 소문자 한 단어 단수형을 사용한다. `util`, `common`, `helper` 패키지는 금지한다.
- 노출 여부는 대소문자로 결정되므로, 패키지 밖에서 쓸 이유가 없는 식별자는 소문자로 시작한다.
- 인터페이스는 구현하는 쪽이 아니라 사용하는 쪽 패키지에 정의하고, 동작으로 명명한다(`Producer`, `Fetcher`). `I` 접두어와 `Interface` 접미사는 금지한다.
- Go 관용 축약어는 허용한다: `ctx`, `err`, `msg`, 짧은 스코프의 `i`, 리시버 한 글자. 그 외에는 의미가 드러나는 이름을 사용한다.
- 패키지명을 식별자에 중복하지 않는다. `kafka.KafkaProducer`가 아니라 `kafka.Producer`.

## 에러 처리

- 에러를 무시하지 않는다. `_ = err` 금지. 의도적으로 무시해야 하면 이유를 주석으로 남긴다.
- 에러를 감쌀 때는 `fmt.Errorf("동작 설명: %w", err)`로 컨텍스트를 추가하고, 판별은 `errors.Is` / `errors.As`를 사용한다.
- 같은 에러를 로깅하고 다시 반환하지 않는다. 처리(로깅 포함)하거나 반환하거나 둘 중 하나만 한다.
- `panic`은 `main`의 초기화 실패(설정 누락, 연결 불가)에서만 허용한다. 메시지 처리 루프 안에서는 금지한다.

## context와 동시성

- 블로킹 가능성이 있는 모든 함수는 `ctx context.Context`를 첫 번째 매개변수로 받는다. 구조체 필드에 context를 저장하지 않는다.
- goroutine을 시작한 쪽이 종료를 책임진다. 종료 신호 전달 수단(context 취소, 채널 close)이 없는 goroutine을 만들지 않는다.
- 채널은 보내는 쪽이 닫는다. 받는 쪽에서 닫지 않는다.
- 모든 바이너리는 SIGINT/SIGTERM을 받으면 context를 취소하고, 처리 중인 메시지를 마무리한 뒤 연결(Kafka reader/writer, Redis, DB 풀)을 명시적으로 닫고 종료한다.
- 공유 상태는 채널 또는 `sync.Mutex`로 보호하고, 새 코드는 `go test -race`를 통과해야 한다.

## Kafka (twmb/franz-go)

- 바이너리당 `kgo.Client` 하나를 만들어 수명 동안 재사용하고, 종료 시 `Close()`로 닫는다.
- 프로듀서: 메시지 키는 마켓 코드(예: `KRW-BTC`)를 사용해 같은 마켓의 순서를 보장한다. 키 없는 발행은 금지한다.
- 비동기 `Produce`의 콜백에서 발행 에러를 반드시 처리한다. 종료 시 `Flush(ctx)`로 미발행 레코드를 비운 뒤 닫는다.
- 컨슈머 클라이언트는 `kgo.DisableAutoCommit()`으로 생성하고, `PollFetches` → 처리 완료 → `CommitRecords` 순서를 지킨다(at-least-once). 자동 커밋에 의존하지 않는다.
- `PollFetches` 결과는 레코드 순회 전에 `fetches.EachError`로 파티션 에러를 먼저 확인한다.
- 컨슈머는 중복 수신을 전제로 멱등하게 작성한다. DB 적재는 유니크 키 기준 `ON CONFLICT DO NOTHING`(또는 갱신), Redis는 최신값 덮어쓰기로 자연 멱등을 유지한다.
- 처리 실패 메시지는 재시도 횟수를 제한하고, 초과 시 원본 페이로드를 로그로 남긴 뒤 커밋하고 넘어간다. 파이프라인 전체를 멈추는 무한 재시도는 금지한다.
- 메시지 구조체 변경 시 기존 필드 제거·타입 변경 같은 breaking change를 금지한다. 필드 추가만 허용한다.

## 계약 경계 (Go ↔ JVM)

- Redis 키/값 포맷을 바꾸면 `backend/api`의 `cache` 패키지를 같은 커밋에서 함께 수정한다.
- DB 스키마는 `backend/api`의 Flyway 마이그레이션이 단독 소유한다. `internal/store`는 INSERT만 하고 DDL을 실행하지 않는다.

## 로깅과 설정

- 구조화 로깅은 표준 `log/slog`를 사용한다. `fmt.Println`, `log.Printf`로 운영 로그를 남기지 않는다.
- 로그에는 판단에 필요한 필드(마켓 코드, 토픽, 오프셋, 에러)를 구조화 필드로 담는다.
- 설정은 환경변수로 받아 `internal/config`에서 로드하고, 시작 시점에 필수 값을 검증해 누락 시 즉시 종료한다. 코드에 접속 정보를 하드코딩하지 않는다.
