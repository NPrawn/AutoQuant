# Go 테스트 컨벤션

`backend/ingest` Go 코드 테스트 작성 시 적용한다.

## 핵심 원칙

- 표준 `testing` 패키지를 기본으로 사용한다. 단언 라이브러리 도입은 사전 확인 없이는 금지한다.
- 케이스가 2개 이상이면 table-driven test로 작성한다.
- 서브테스트 이름(`t.Run`)은 한국어로 동작을 설명한다. 구현이 아닌 동작을 설명한다.
- 테스트 하나(케이스 하나)에 동작 하나만 검증한다.
- 비공개 함수를 직접 테스트하지 않고 패키지의 공개 동작을 통해 테스트한다.
- 테스트는 실행 순서와 다른 테스트의 상태에 의존하지 않는다.
- 새 테스트는 `go test -race ./...`를 통과해야 한다.

## 테스트 대역

- Mock 라이브러리 대신 작은 인터페이스와 손으로 작성한 fake를 사용한다.
- 테스트 대상 외부의 경계(Kafka, Redis, DB, Upbit API)만 대역으로 치환한다. 순수 함수와 단순 구조체는 치환하지 않는다.
- 대역 치환이 가능하도록 의존성은 구체 타입이 아니라 사용하는 쪽에 정의한 인터페이스로 받는다.
- Upbit 페이로드 파싱 테스트는 실제 응답을 본뜬 JSON 픽스처를 사용하고, 픽스처는 테스트 파일 가까이 또는 `testdata/` 디렉토리에 둔다.

## 단위 테스트와 통합 테스트

- 기본은 외부 프로세스 없이 도는 단위 테스트다. `go test ./...`가 로컬 도구 설치만으로 통과해야 한다.
- 실제 Kafka·Redis·PostgreSQL이 필요한 검증은 빌드 태그 `//go:build integration`으로 분리하고, 실행 방법(필요한 docker 환경)을 해당 테스트 파일 주석에 남긴다.
- 통합 테스트에서 검증한다: 오프셋 커밋 시점, 재연결 동작, `ON CONFLICT` 멱등성. 단위 테스트로 흉내 내지 않는다.

## 단언

- 구현 세부사항이 아닌 의미 있는 결과를 단언한다.
- 실패 메시지에 기대값과 실제값을 모두 담는다: `got %v, want %v` 형식.
- 구조체 비교는 필드별 단언 대신 `reflect.DeepEqual` 또는 비교 함수로 전체를 비교하고, 다른 부분이 드러나게 한다.
- 에러 검증은 `err != nil` 여부만 보지 않고 `errors.Is` / `errors.As`로 기대한 에러인지 확인한다.

## 금지 사항

- 테스트 하나에서 여러 동작 검증
- `time.Sleep`으로 비동기 결과 대기 (채널·context로 동기화한다)
- 단위 테스트에서 실제 네트워크·DB 사용
- 실행 순서에 의존하는 테스트, 공유 전역 상태를 남기는 테스트
