## 티켓 제목

[`../../docs/git-convention.md`](../../docs/git-convention.md)의 `[영역] 대상과 작업 내용` 형식을 따른다. 영역은 `AI`다.

| 유형 | 제목 |
|---|---|
| 스토리 | `[AI] 프롬프트 로더와 응답 정제 기반 구성` |
| 하위 작업 | `[AI] 프롬프트 파일 로더와 자리표시자 치환 구현` (E-1) |

| | `[AI] 전략 요청 자연어 발화 수집` (J-1) |

작업 ID(E-1 등)는 제목에 넣지 않는다. 정본이 Jira 키도 제목에 안 쓰게 하므로 문서와 보드는 **본문에서** 이 ID로 연결한다.

## 이 구간의 성격

전략 도메인 명세가 아직 없다. [REVIEW-STRATEGY-MVP.md](REVIEW-STRATEGY-MVP.md) G절의 15개 질문 중 1~7번이 미답이라 `app/core/schema.py`를 열 수 없고, 그 뒤에 D-2·D-3·E-3·E-4·G·H가 전부 줄 서 있다.

그래서 이 구간은 **스키마를 건드리지 않고 지금 만들 수 있는 것만** 모았다. 넷 다 명세가 와도 다시 쓰지 않는다.

| 작업 | 왜 지금 되나 |
|---|---|
| E-1 프롬프트 로더 | 파일을 읽어 캐시하는 일이다. 내용과 무관하다 |
| E-2 프롬프트 초안 | 자리표시자 규약과 뼈대만 잡는다. 도메인 규칙은 K-3에서 채운다 |
| D-1 응답 텍스트 정제 | 문자열에서 JSON 본문을 잘라내는 일이다 |
| J-1 발화 수집 | 사용자가 실제로 무엇을 어떻게 말하는지 모으는 일이다 |

**`app/core/schema.py`를 만들지 않는다.** 파일 자리도 만들지 않는다.

## 작업 위치와 브랜치

작업 디렉토리는 저장소 `S15P21A107`의 `ai/`다.

**브랜치·커밋·MR 규칙은 [`../../docs/git-convention.md`](../../docs/git-convention.md)를 따른다.** 여기 옮겨 적지 않는다.

이 구간에만 해당하는 것 둘.

- 스토리 티켓을 만들면 Jira 자동화가 `develop`에서 브랜치를 함께 만든다. 손으로 만들지 말고 `git fetch` 후 받아 쓴다
- **하위 작업마다 브랜치를 파지 않는다.** 스토리 하나에 브랜치 하나, 하위 작업은 커밋 하나씩이다. 넷은 파일이 겹치지 않아 한 브랜치에 들어간다 — `app/services/prompt_builder.py`, `app/prompts/*.txt`, `app/services/validator.py`, `tests/fixtures/user_inputs.md`

순서 제약은 E-1 → E-2 하나뿐이다. D-1과 J-1은 아무 때나 끼운다.

완료 보고에 커밋 SHA를 포함한다. SHA 없는 보고는 반려한다.

## 이미 있는 것

Epic A·C·F가 끝나 있다. 새로 만들지 말고 가져다 쓴다.

| 쓸 것 | 어디 |

# E-1 프롬프트 로더 (4h)

`app/services/prompt_builder.py`

## 만들 것

`app/prompts` 아래 `.txt` 파일을 읽어 이름으로 꺼내 쓰는 로더.

- **기동 시 한 번 읽고 캐시한다.** 요청마다 디스크를 치지 않는다
- **파일이 없으면 기동에 실패한다.** 첫 요청에서 죽으면 안 된다. A-2의 설정 객체가 필수 환경변수에 대해 하는 것과 같은 방식이다
- 파일 인코딩은 UTF-8로 고정한다

## 디렉토리 위치를 두 곳에 적지 않는다

`app/api/v1/health.py`가 이미 `PROMPTS_DIRECTORY`를 갖고 있다.

```python
PROMPTS_DIRECTORY = Path(__file__).parents[2] / "prompts"
```

같은 경로를 로더에도 다시 적으면 한쪽만 고쳐지는 날이 온다. **경로 상수는 한 곳에 두고 양쪽이 그것을 임포트한다.** 어느 쪽으로 옮길지는 재량이지만 두 벌로 두면 반려한다.

## 치환 기계도 여기서 만든다

자리표시자를 값으로 바꾸는 함수 하나를 같이 둔다. **값을 만드는 건 E-3·E-4고 스키마를 기다린다. 여기서는 기계만 만든다.** 치환 대상 맵을 받아 바꿔 끼우고, 끝난 뒤 자리표시자 잔재가 남았으면 오류를 낸다.

**`str.format()`을 쓰지 마라.** 자리표시자 규약이 이중 중괄호(`{{dsl_schema}}`)인데 `.format`은 `{{`를 여는 중괄호 하나로 이스케이프 처리한다. 규약과 정면으로 부딪친다. 게다가 프롬프트 본문에 JSON 예시가 들어가는 순간 중괄호마다 터진다. `str.replace`나 정규식으로 간다.

잔재 검사를 넣는 이유는 조용히 실패하는 걸 막기 위해서다. 치환이 안 된 자리표시자가 그대로 LLM에 넘어가면 오류 없이 이상한 답만 돌아온다.

## 완료 조건

- 기동 시 프롬프트 파일이 캐시된다
- `app/prompts`를 비우고 기동하면 실패한다
- 같은 파일을 두 번 요청해도 디스크를 다시 읽지 않는다
- 치환 후 자리표시자가 남아 있으면 오류가 난다

**선행** A-2

# E-2 프롬프트 초안 (4h)

`app/prompts/system.txt`, `create.txt`, `edit.txt`, `retry.txt`

## 자리표시자 규약

다섯 개만 쓴다. 각각 이중 중괄호로 감싼다.

| 자리표시자 | 무엇이 들어가나 |
|---|---|
| `dsl_schema` | B-5가 만들 JSON Schema |
| `user_input` | 사용자 발화 |
| `current_strategy` | 수정 대상 전략 |
| `previous_output` | 검증에 실패한 직전 LLM 출력 |
| `validation_errors` | D-3이 만들 재시도용 오류 문구 |

**이 다섯 개 밖의 자리표시자를 만들면 반려한다.** 늘리는 순간 조립부와 프롬프트가 따로 놀기 시작한다.

## 파일 4종의 역할

| 파일 | 언제 쓰나 |
|---|---|
| `system.txt` | 항상. 역할 지시 + 스키마 주입 + 출력 규칙 |
| `create.txt` | `current_strategy`가 null일 때. 처음부터 만든다 |
| `edit.txt` | `current_strategy`가 있을 때. 무엇을 바꿀지만 판단한다 |
| `retry.txt` | 검증 실패 후. 직전 출력과 오류를 붙인다 |

## 도메인 규칙을 쓰지 마라

기본값 정책, 지표별 관행값, 지원 범위 밖 요청 처리는 **K-3에서 쓴다.** 명세가 없는 지금 적으면 곧 지운다. 구조가 돌아가는 최소한만 적는다.

## 반드시 넣을 지시 하나 (결정 5)

**입력이 전략 설명이 아니거나 내용이 부실해도 거부하지 않고 전략을 만든다.** 대신 임의로 정한 값을 `assumptions`에 한 줄씩 적게 한다.

"돈 많이 버는 전략 만들어 줘"에 전 필드를 기본값으로 채웠다면 그 사실이 사용자에게 전달돼야 한다. 이게 없으면 사용자는 자기가 말하지 않은 값이 들어간 줄 모른다. `NotAStrategyError`를 넣지 않기로 한 이유가 여기 있다([DECISIONS.md](DECISIONS.md) 결정 5).

## 구조화 출력이 통과한다 — 형식 지시를 장황하게 쓰지 마라

F-3 실측에서 `response_format`의 `json_schema`가 GMS 프록시를 HTTP 200으로 통과했다([DECISIONS.md](DECISIONS.md) 결정 4). E-3에서 스키마를 API 인자로 직접 주입하므로, 프롬프트에 "반드시 JSON만 출력하라"를 여러 문단에 걸쳐 반복할 필요가 없다. 한 줄이면 된다.

## 완료 조건

- 파일 4종이 자리표시자 규약대로 작성된다
- `curl localhost:8000/health/ready`가 200을 준다 (지금은 503이다)

**선행** E-1

# D-1 응답 텍스트 정제 (3h)

`app/services/validator.py`

## 만들 것

LLM 응답 텍스트에서 JSON 본문만 잘라내는 함수 하나.

허용하는 정제는 **두 가지뿐이다.**

1. 코드 펜스(```` ```json ```` … ```` ``` ````) 제거
2. 첫 여는 중괄호부터 마지막 닫는 중괄호까지 잘라내기

## 관대하게 만들지 마라

정제를 늘릴수록 LLM의 형식 위반을 눈감아 준다. 위 둘을 넘어서는 보정(따옴표 교정, 후행 쉼표 제거, 주석 제거 등)을 넣으면 반려한다. 그 이상은 프롬프트로 잡는다.

## 이 작업은 fallback이다

F-3에서 구조화 출력이 통과했으므로 실제 운용에서 이 코드가 탈 일은 드물다. 그래도 만든다 — 프록시나 모델이 바뀌면 실측이 무효가 되고, 그때 코드가 있으면 스위치 한 번으로 끝난다.

**우선순위가 낮다는 뜻이지 대충 해도 된다는 뜻이 아니다.** 정제가 틀리면 조용히 잘못된 JSON이 통과한다.

## 스키마를 임포트하지 마라

이 작업은 문자열 처리다. `app/core/schema.py`를 임포트하지 않는다. 파싱과 검증은 D-2고, 그건 스키마가 확정된 뒤다.

## 완료 조건

아래가 각각 JSON 본문으로 정제된다.

- 순수 JSON 객체
- 코드 펜스로 감싸인 JSON
- "네, 다음과 같습니다:" 뒤에 JSON, 그 뒤에 안내 문장

빈 문자열과 중괄호가 닫히지 않은 문자열은 정제 단계에서 죽지 않고 다음 단계(D-2)로 넘어간다. **이 함수는 예외를 던지지 않는다.**

**선행** A-1

# J-1 사용자 발화 수집 (8h)

`tests/fixtures/user_inputs.md`

## 만들 것

전략을 요청하는 자연어 문장 30~50건. 갈래와 **출처**를 붙여 표로 적는다.

## LLM에게 30건을 시키지 마라 — 반려 사유다

LLM에게 맡기면 5분이면 끝난다. 그런데 그 목록은 LLM이 쓰는 말투다. L-2에서 통과율 90%를 재는데 입력도 LLM이 만들고 처리도 LLM이 하면 같은 분포 안에서 자기 채점하는 셈이 된다. 목표가 자기충족된다.

실제 사용자는 "RSI 30 이하 종목 중 거래대금 상위 5개를 선정하는 전략"이라고 치지 않는다. "알티 요즘 오르는거 사고싶은데"라고 친다. 그 차이를 모으는 게 이 작업의 전부다.

## 셋으로 나눠 채운다

**코어 20건 — 팀원에게 받는다.** 여섯 명이니 한 사람당 3~4문장이다. 질문은 한 줄이면 된다.

> 코인 자동매매 전략을 말로 설명하면 만들어주는 서비스야. 검색창에 뭐라고 칠 것 같아? 다듬지 말고 떠오르는 대로 3개만.

화면 목업 스크린샷을 같이 붙이면 답이 구체적으로 온다. **"다듬지 말고"가 핵심이다.** 정제된 문장을 받으면 코어를 따로 두는 의미가 없다.

**확장 15건 — 코어를 사람이 비튼다.** 줄임말(비트코인 → 비티), 조사 생략, 오타, 반말과 존댓말 전환. 코어 하나에서 변형 하나씩 뽑는다.

**경계 10건 — 의도적으로 어려운 것을 짓는다.** 여기는 지어내도 된다. 흔치 않은 입력을 일부러 찾는 자리라 자연스러움보다 커버리지가 중요하다.

- 전략이 아닌 입력 — "안녕", "비트코인 지금 사도 됨?"
- 지원 범위 밖 — "5% 빠지면 사고 10% 오르면 팔아" (진입·청산 신호형)
- 모순 조건 — "변동성 제일 낮으면서 수익률 제일 높은 거"
- 범위 초과 — "1000일 수익률로 정렬" (`lookback_days` 상한 365)

## 갈래 여섯

| 갈래 | 예 |
|---|---|
| 단순 랭킹 요청 | "최근 한 달 많이 오른 코인 5개 사줘" |
| 조건이 붙은 요청 | "거래량 늘어난 것 중에서 수익률 높은 3개" |
| 여러 조건을 쌓는 요청 | "RSI 30 아래면서 거래대금 상위인 것들 중 변동성 낮은 순으로" |
| 모호한 요청 | "돈 많이 버는 전략" |
| 전략이 아닌 입력 | "안녕하세요", "비트코인 지금 사도 되나요" |
| 지원 범위 밖 요청 | "5% 떨어지면 사고 10% 오르면 팔아" |

## 파일 형식

| ID | 문장 | 갈래 | 출처 |
|---|---|---|---|
| U-01 | 요즘 잘 오르는 코인 5개만 골라줘 | 단순 랭킹 | 팀원 |
| U-02 | 요즘 잘오르는거 5개 | 단순 랭킹 | 변형 |
| U-03 | 5% 빠지면 사고 10% 오르면 팔아 | 범위 밖 | 작성 |

**출처 컬럼을 빼면 반려한다.** L-2에서 통과율을 출처별로 쪼개 보기 위한 것이다. 팀원 문장에서만 통과율이 떨어지면 프롬프트가 정제된 입력에만 맞춰졌다는 뜻이고, 그게 실전에서 터지는 지점이다. 컬럼이 없으면 이걸 볼 수 없다.

## 기대 DSL을 적지 마라

명세가 확정되면 K-4에서 붙인다. 지금 적으면 임시 스펙 기준이라 통째로 버린다. **입력 문장·갈래·출처만 적는다.**

## 이 목록이 전략팀에 넘어간다

사용자가 실제로 무엇을 어떻게 말하는지 알고 도메인을 설계하는 것과 모르고 하는 것은 다르다. 특히 전략이 아닌 입력과 지원 범위 밖 요청이 얼마나 들어오는지가 결정 5와 향후 범위 논의의 근거가 된다.

## 완료 조건

- 문장 30건 이상
- 여섯 갈래가 모두 채워진다. 한 갈래에 최소 3건
- 각 문장에 갈래와 출처가 붙는다
- 출처가 `팀원`인 문장이 15건 이상이다

**선행** 없음

# 반려 사유 정리

1. `app/core/schema.py`를 만들거나 임포트함
