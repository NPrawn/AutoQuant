## 좋은 데이터의 조건

대회 데이터가 갖춰야 할 성질을 넷으로 나눈다. 넷을 한 번에 다루면 무엇이 좋아졌는지 말할 수 없다.

| 조건 | 뜻 | 지금 상태 |
|---|---|---|
| 1. 값이 진짜 같은가 | 실제 시장 통계와 구분되지 않는가 | 2단계로 잰다. 다섯 지표 중 둘이 기준 밖 |
| 2. 새로운가 | 아무도 백테스트해 본 적 없는 경로인가 | 측정 없음 |
| 3. 실력을 가리는가 | 같은 전략이 다른 벌에서도 비슷한 순위인가 | 표본 5벌로 잰 값 하나뿐 |
| 4. 악용이 막히는가 | 데이터 특유의 패턴을 긁어 이길 수 있는가 | 3단계가 검정력 없음 |

**이 설계는 1과 3만 다룬다.** 2와 4를 재려면 전략 격자를 대량으로 돌려야 하는데, 그 도구가 3의 산출물이다. 도구를 먼저 만들고 2·4는 그다음 회차에서 잡는다.

허용 범위는 실제 값을 시간순 앞뒤 절반으로 갈라 잰 KS 거리다 (ADR-0015). 실제 시장이 자기 자신과 다른 만큼은 봐준다는 뜻이다.

### 중앙값을 읽을 때 주의

이음매 지표는 `log(경계 뒤 24시간 변동성 / 경계 앞 24시간 변동성)` 이다. 중앙값 0.053은 실제 주 경계에서 변동성이 보통 5.5% 오른다는 뜻이고, 0.073은 생성 이음매에서 7.6% 오른다는 뜻이다. **두 값의 비(1.37)를 "37% 더 튄다"로 읽으면 안 된다.** 중앙값은 분포의 위치만 말하고, 튀는 정도는 퍼짐에 들어 있다. KS가 잡는 것은 분포 전체의 차이다.

지금 리포트는 중앙값과 KS만 남긴다. 그래서 "얼마나 더 튀는지"를 사후에 말할 수 없다. 분위수를 같이 남기는 것을 이 설계에 넣는다.

## 원인 가설

두 현상이 한 원인에서 나온다고 본다. **주 안은 실제 그대로 두고, 주 사이는 라벨 세 개(상승·횡보·하락)의 전이 비율로만 잇는다.**

- 경계에서 변동성·거래량 수준이 이어지지 않는다. 조용한 주 뒤에 격동하는 주가 붙는다. 가격만 비율로 맞추고 나머지는 원래 주의 값을 그대로 쓴다.
- 여러 주에 걸친 흐름이 실제보다 빨리 끊긴다. 주 수익률 자기상관이 실제의 57%다. 라벨 세 단계는 수익률 부호만 이어 주고 강도·변동성은 이어 주지 않는다.

흐름이 끊기면 추세를 따라가는 전략이 불리해지고, 데이터셋마다 유리한 전략이 달라진다. 조건 1의 문제가 조건 3의 원인이기도 하다는 뜻이다. 이 가설은 아래 측정으로 확인한다.

## 설계

### 1. 이음매 스케일 정합

지금 `stitch`는 주를 붙일 때 가격에만 비율을 곱한다.

```
k = 생성 데이터 직전 종가 / 원래 주 직전 종가          # 가격
ratio = 생성 직전 4주 거래량 중앙값 / 원래 주 직전 4주 거래량 중앙값   # 거래량
```

거래량은 4주 중앙값으로 맞추므로 경계 바로 앞뒤 수준은 안 맞는다. 변동성은 아예 안 맞춘다.

변동성 정합을 넣는다. 붙일 주의 첫 24시간 수익률 표준편차를 직전 주 마지막 24시간 수준으로 끌어당긴다.

```
s_before = 생성 데이터 마지막 24시간 시간당 수익률 표준편차
s_after  = 붙일 주 첫 24시간 시간당 수익률 표준편차
g = (s_before / s_after) ** α        # α 는 0~1, 정합 강도
r'[t] = 1 + (r[t] − 1) × w(t) × g + (r[t] − 1) × (1 − w(t))
```

`w(t)`는 경계에서 1로 시작해 램프 기간(기본 24시간) 동안 0으로 내려가는 가중치다. 경계 근처만 맞추고 주 안쪽은 원래 모양을 지킨다. `α = 0`이면 지금과 같고 `α = 1`이면 완전히 맞춘다.

거래량도 같은 모양으로 경계 램프를 더한다. 4주 중앙값 비율은 그대로 두고, 경계 앞뒤 24시간만 추가 계수를 곱한다.

가격은 수익률을 다시 누적해 만들고 호가 단위에 맞춰 스냅한다. 고가·저가는 종가 대비 비율을 유지한 채 따라 움직인다. 봉 검사(OHLC 순서, 호가 격자, 체결 단가가 저가~고가 안)는 지금 기준 그대로 전수 통과해야 한다.

**위험.** 참가자에게 설명하는 문장이 바뀐다. 지금은 "한 주 안의 움직임은 실제 그대로"인데, "주 경계 하루는 앞 주 수준에 맞춰 크기를 조절한다"가 붙는다. 조절 대상이 크기뿐이고 모양은 그대로라는 점은 유지된다. `α`와 램프 길이는 2단계 결과를 보고 고른다.

### 2. 전이 조건 확장 (조건부)

라벨을 수익률 3분위 × 변동성 2수준으로 늘려 전이 행렬을 6칸으로 만든다. 지속성이 살아나는지 본다.

**먼저 확인할 것이 있다.** 104주 풀을 6칸으로 나누면 칸마다 평균 17주다. 한 칸이 5주 아래로 떨어지면 전이 확률 추정이 못 쓰게 된다. 풀을 세어 보고 칸이 너무 얇으면 이 항목은 버린다. 이전에 "변동성 수준이 같은 주만 고르기"를 실험했다가 풀이 줄어 긴 흐름이 더 조용해진 전례가 있다 (ADR-0015 검토한 대안).

1번을 먼저 하고, 1번만으로 자기상관이 실제 쪽으로 오지 않으면 2번을 본다.

### 3. 검증 리포트에 분위수를 남긴다

`checks.compare`가 지금 남기는 것은 표본 수, 중앙값, KS, 허용 범위다. 여기에 p10·p25·p75·p90과 절댓값 평균을 더한다. 값 다섯 개를 더 담는 것뿐이고 계산은 이미 있는 배열에서 나온다.

이게 있어야 "이음매가 실제보다 얼마나 더 튀는가"에 답할 수 있다. 지금은 KS 하나로 실패만 알 뿐 크기를 말할 수 없다.

### 4. 검증용 파이썬 백테스터

3·4단계는 Spring API에 제출하고 worker가 큐로 받아 돌린다. 390회에 44분 걸렸다. 신뢰도를 제대로 재려면 수천 회가 필요한데 이 구조로는 못 한다.

검증에 필요한 것은 순위지 체결가가 아니다. 캔들에서 팩터를 계산해 리밸런싱 시점마다 상위 N을 고르는 코드를 따로 둔다.

- 입력: 생성기가 만든 1시간봉 배열, 전략 정의(팩터·기간·연산자·임계값·상위 N·리밸런싱·봉 간격)
- 출력: 시점별 자산 가치, 누적 수익률, 최대 낙폭, 평균 투자 비중
- 근사: 체결은 다음 봉 시가, 수수료 0.05%, 슬리피지 10bp를 그대로 넣는다. 부분 체결·호가 단위·주문 순서는 무시한다

**엔진과의 대조가 이 도구의 합격 조건이다.** 1회차 데이터 4벌에서 전략 10개를 돌려 엔진 결과와 비교한다. 40회다. 누적 수익률 절대 오차보다 **순위 일치**가 기준이다. 4벌 각각에서 순위 상관 0.9 이상이면 3·4단계 검증에 쓴다. 미달이면 원인을 찾아 고치고, 못 맞추면 이 도구를 버리고 엔진으로 돌아간다.

절대 점수(참가자에게 나가는 값)는 언제나 엔진이 낸다. 이 백테스터는 검증 전용이고 운영 경로에 들어가지 않는다.

### 5. 신뢰도 측정

같은 조건의 측정을 `k`번 평균하면 신뢰도가 `kρ / (1 + (k−1)ρ)` 로 오른다. `ρ`는 데이터셋 한 벌의 재현성이다. 지금 가진 추정은 0.093 하나뿐이라 이것부터 제대로 잡는다.

**실험 설계**

- 데이터셋: 같은 구간·같은 파라미터로 시드만 바꿔 20벌
- 전략: 팩터 6개 × 기간 4단계 × 상위 3·5·10 × 리밸런싱 3종에서 200개 격자
- 봉 간격: 1D 로 고정한다. 1H는 계산이 24배다
- 측정: 벌 쌍마다 순위 상관 → `ρ` 분포. `k = 1·3·5·10·20` 의 신뢰도 곡선

**같이 재는 것 셋**

1. 평가 13주와 26주에서 `ρ`가 얼마나 다른가. 벌을 늘리는 것과 기간을 늘리는 것 중 어느 쪽이 싼지 갈린다
2. 13주를 3~4주 구간으로 쪼개 점수를 평균하면 `ρ`가 얼마나 오르는가. 데이터 추가 비용이 0이라 먼저 본다
3. 위 1번 이음매 정합 전후로 `ρ`가 어떻게 변하는가. 원인 가설의 확인이다

### 6. 구간 평균 채점 (검토만)

5번의 2항에서 효과가 확인되면 채점 규칙 변경 후보가 된다. 평가 구간 전체에서 수익률·낙폭을 한 번 재는 대신, 구간을 쪼개 점수를 평균한다.

이 설계에서는 **재기만 하고 바꾸지 않는다.** 채점 규칙은 백엔드 `ContestScoreCalculator`와 ADR-0003에 걸려 있고, 회차 중에 바꾸면 이미 채점된 결과를 다시 써야 한다. 숫자를 먼저 확보하고 별도 티켓으로 올린다.

## 통과 기준

**조건 1 (이음매·지속성)**

- 봉 검사 위반 0건. 지금과 같다
- 이음매 변동성 변화와 거래량 변화의 KS가 허용 범위 이하
- 주 수익률 자기상관 중앙값이 지금(0.081)보다 실제(0.143) 쪽으로 이동. 실제를 넘어서지는 않는다
- 월 변동성과 최대 낙폭이 계속 통과

이음매 둘이 통과하고 자기상관이 그대로면 절반의 성공이다. 이음매를 고쳤지만 지속성은 다른 문제라는 뜻이고, 2번(전이 조건 확장)으로 넘어간다.

**조건 3 (신뢰도)**

합격선을 두지 않는다. 지금은 `ρ`를 모르는 것이 문제지 특정 값에 못 미치는 것이 문제가 아니다. 산출물은 판정이 아니라 **근거표**다.

- `k`별 신뢰도 곡선
- 평가 기간 13주 대 26주
- 구간 평균 채점의 효과
- 이음매 정합 전후 비교

이 표를 놓고 "장세당 몇 벌, 평가 몇 주"를 정한다.

## 측정 절차

1. 분위수 기록을 먼저 넣고 (설계 3), 지금 생성기로 2단계를 돌려 기준선을 다시 남긴다
2. 이음매 정합을 넣고 (설계 1) `α`와 램프 길이를 몇 가지로 돌려 2단계를 비교한다. 백테스트가 필요 없어 한 번에 몇 분이다
3. 통과 기준을 넘는 설정을 고르고, 안 넘으면 전이 조건 확장 (설계 2)으로 간다
4. 파이썬 백테스터를 만들고 (설계 4) 엔진과 대조한다
5. 신뢰도를 잰다 (설계 5)
6. 근거표를 이 문서의 측정 결과 절에 남긴다

1~3은 캔들 통계만 쓴다. 4~5는 백테스트가 필요하지만 엔진을 안 탄다.

|---|---|
| 봉 검사 위반 0건 | 통과 |
| 이음매 두 지표가 허용 범위 이하 | 통과 |
| 월 변동성·최대 낙폭 계속 통과 | 통과 |
| 주 수익률 자기상관이 실제 쪽으로 이동 | **변화 없음** |

자기상관은 네 설정에서 모두 0.081로 같았다. 이 지표는 뽑힌 주들의 수익률 순서에서 나오므로 잇는 방식과 무관하다. 구조상 이음매 정합으로는 못 움직인다.

실제 분포와 비교하면 차이가 뚜렷하다. 실제는 p10이 +0.097이라 거의 모든 구간에서 양수인데, 생성 데이터는 p10 −0.112, p25 −0.010으로 4분의 1이 음수다. 오르면 이어서 오르는 성질이 사라진 정도가 아니라 뒤집힌 구간이 생긴다. 지금 이 지표가 통과로 나오는 건 허용 범위가 0.581로 넓어서다.

설계에 적은 대로 **전이 조건 확장(설계 2)으로 넘어간다.** 104주 풀을 수익률 3분위 × 변동성 2수준으로 나눴을 때 칸이 너무 얇아지지 않는지 세는 것이 먼저다.

## 범위 밖

- **조건 2(새로운가)와 4(악용)의 측정.** 4번 도구가 생긴 다음 회차에서 잡는다
- **채점 규칙 변경.** 숫자만 낸다. 규칙은 별도 티켓
- **원본 풀 깊이와 universe 크기.** 104주 구간에서 43주를 뽑는 구조와 종목 10개는 그대로 둔다. 구간을 넓히거나 여러 구간에서 뽑는 것은 ADR-0011을 고치는 일이라 따로 본다
- **생성 모델(GAN·diffusion) 도입.** 이음매가 없어지고 표본이 무한해지지만, 왜 타당한지 설명할 수 없다. ADR-0008에서 노이즈 변조를 기각한 이유가 그대로 돌아온다
- **2회차 데이터 생성.** 제출 기간이 정해져야 시작한다. 이 설계가 끝나면 고친 생성기로 만든다
