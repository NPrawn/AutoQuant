# 대회 데이터 생성·검증 설계

- 상태: 승인 (2026-09-14)
- 결정 기록: [docs/adr](../../docs/adr/README.md) ADR-0001 ~ ADR-0013
- 구현: 에픽 [S15P21A107-215](https://ssafy.atlassian.net/browse/S15P21A107-215)의 스토리. 파일 구성과 실행 명령은 이 문서에 적지 않고 코드와 스토리에서 본다.

## 1. 목표

연습 백테스트는 2018~2025 실제 데이터를 그대로 쓴다. 대회는 이 데이터를 조작해 누구도 백테스트해 본 적 없는 시장으로 채점한다.

이번 에픽의 목표는 **조작한 데이터로 로컬에서 대회를 한 번 열어 테스트하는 것**이다.

**완료 조건:** 실제 원본으로 ADR-0012 1·2단계 확인 결과를 남기고, 로컬 대회 채점표를 남긴다. ADR-0011(조작 방식)의 채택은 3·4단계까지 통과한 뒤에 한다.

## 2. 범위

| 이번에 한다 | 하지 않는다 |
|---|---|
| 대회 데이터 생성 (실제 주를 뽑아 잇기) | 운영 배치, `contest` 스키마, 대회용 캔들 provider, 제출 시 팩터 기간 검증 (백엔드, ADR-0006·0013) |
| 봉 검사, ADR-0012 1·2단계 확인 | ADR-0012 3·4단계 실험 |
| 로컬 백엔드에서 대회 한 번 실행과 채점 | 대회 참가·제출 API, 대회 화면 |

## 4. 데이터

### 4.1 원본

- **범위:** 2018-01-01 이상, 2026-01-01 미만(UTC)의 1시간봉. 종목, 시각, 시가·고가·저가·종가, 거래량, 거래대금을 쓴다.
- **후보 종목:** 오늘 거래대금 상위 30개(스테이블코인 제외, 2026년 상장 제외). 종목마다 상장일이 달라 8년 내내 있는 종목은 6개뿐이다.
- **universe:** 대회마다 고른 104주 구간 내내 거래된 후보 종목. 이런 종목이 10개 미만인 구간은 고르지 않는다. 가격이 1원 아래로 내려가는 종목(SHIB)은 백엔드 체결가 단위가 1원이라 로컬 대회에서 뺐다.
- **확보:** 업비트 API로 받은 1시간봉 약 104만 개. 레포 밖 로컬 파일이라 커밋하지 않는다.

### 4.2 대회 데이터

| 데이터셋 | 내용 |
|---|---|
| `GENERAL` | 일반장. 고른 구간의 실제 전이 비율대로 주를 잇는다 |
| `BULL` / `BEAR` / `SIDEWAYS` | 일반장처럼 뽑은 후보 중 평가 13주 수익률이 목표 범위인 것 |

- 각 18주(워밍업 5 + 평가 13)다. 종목당 1시간봉 최대 3,024개, 4시간봉 756개, 일봉 126개다.
- 로컬 테스트에서는 `market_data.minute_candle`에 그대로 넣을 수 있는 형태로 만든다. 운영 형식은 ADR-0006을 따른다.

## 5. 생성 알고리즘 (ADR-0011)

### 5.1 파라미터

| 이름 | 기본값 | 의미 |
|---|---|---|
| 블록 길이 | 7일 | |
| 블록 시작 | 월요일 00:00 UTC | 목요일과 4단계에서 비교 |
| 워밍업 | 5주 | 팩터 기간 상한을 함께 정한다 (ADR-0013) |
| 평가 | 13주 | |
| 구간 길이 | 104주 | 대회마다 시드로 무작위 선택 |
| 구간 최소 종목 수 | 10 | 구간 내내 거래된 후보 종목 수 |
| 장세 후보 수 | 1,000 | |
| 상승장 목표 | +20% ~ +30% | 평가 13주 universe 균등 보유 수익률 |
| 하락장 목표 | -20% ~ -10% | 〃 |
| 횡보장 목표 | -3% ~ +3% | 〃 |
| 거래량 기준 | 4주 | 거래량 수준을 맞출 기준 기간 |
| 가상 날짜 시작 | 2030-01-01 이후 첫 블록 시작 요일 | 월요일이면 2030-01-07 |

### 5.2 절차

1. **구간과 블록 풀.** 104주 구간 중 구간 내내 거래된 후보 종목이 10개 이상인 구간을 시드로 하나 고르고, 그 종목을 universe로 삼는다. 구간을 블록 시작 요일 00:00 UTC부터 7일씩 자른다. universe 모든 종목이 그 주 시작 전에 첫 캔들이 있고 그 주가 끝난 뒤에도 캔들이 있는 주만 풀에 넣는다. 거래가 없어 비어 있는 시간은 원본 그대로 비워 둔다.
2. **라벨.** 주마다 universe 균등 보유 수익률(종목별 `주 마지막 종가 / 직전 봉 종가 − 1`의 평균)을 구한다. 풀 전체를 3등분해 하락·횡보·상승을 붙이고, 실제로 이어진 두 주의 라벨 쌍을 세어 전이 비율을 만든다.
3. **일반장.** 첫 주 라벨은 라벨 비율대로, 이후는 전이 비율대로 뽑는다. 라벨이 정해지면 그 라벨의 주에서 하나를 고른다. 한 데이터셋 안에서 같은 주는 두 번 쓰지 않는다.
4. **장세.** 일반장과 같은 방식으로 18주를 뽑은 후보를 만들고, 평가 13주 수익률이 목표 범위에 드는 첫 후보를 쓴다. 같은 라벨의 주로만 채우면 코인의 주간 변동이 커서 목표에 닿지 않는다(ADR-0011). 후보 수 안에서 찾지 못하면 실패로 끝낸다.
5. **잇기.**
   - 가격: 주마다 모든 가격에 `생성 데이터 직전 종가 / 원래 주 직전 종가`를 곱하고 호가 단위에 맞춘다. 호가 단위는 원본에서 가격대(10의 거듭제곱 구간)별로 관측한 가장 작은 가격 차이다.
   - 거래량: `생성 데이터 직전 4주 거래량 중앙값 / 원래 주 직전 4주 거래량 중앙값`을 곱한다. 거래대금에는 가격 비율과 거래량 비율을 함께 곱해 평균 체결가가 저가~고가 안에 남게 한다.
6. **시각.** `i`번째 주의 봉 시각은 `가상 날짜 시작 + i주 + (원래 봉 시각 − 원래 주 시작)`이다. 요일과 시간대가 원래 주와 같다.
7. **집계.** 4시간봉과 일봉은 생성한 1시간봉을 UTC 기준으로 잘라 집계한다 (ADR-0005).
8. **기록.** 뽑은 주 목록, 순서, 시드를 남긴다.

### 5.3 결정성

난수는 시드 하나로 만들고 호출 순서를 고정한다. 원본, 시드, 파라미터가 같으면 같은 데이터가 나온다.

## 6. 검증 (ADR-0012)

### 6.1 실제 비교 기준

블록 풀에서 실제로 이어진 18주를 한 주씩 밀어 실제 구간을 만든다 (최대 약 400개). 생성 데이터의 통계가 이 구간들의 분포 안에 있는지 본다.

### 6.2 단계

| 단계 | 필요한 것 | 통과 기준 요약 | 이번 에픽 |
|---|---|---|---|
| 1. 가능한가 | 원본 | 라벨마다 30주 이상, 장세 후보가 목표 범위에 도달 | 실행 |
| 2. 값이 진짜 같은가 | 원본 | 봉 검사 위반 0건, 이음매 변동성·거래량 변화와 긴 흐름 통계(주 수익률 자기상관, 4주 변동성, 최대 낙폭)가 실제 구간과 KS 검정에서 구분되지 않음 | 실행 |
| 3. 외워 맞추기가 막히는가 | 엔진 | 과적합 전략의 성적 하락이 견고한 전략보다 뚜렷하게 큼 | 로컬 대회 결과를 본 뒤 설계 |
| 4. 공정한가 | 엔진 | 유형별 순위 차이, 시드 간 순위 상관, 이음매 요일 차이가 실제 구간끼리의 차이 범위 안 | 〃 |

세부 기준과 실패 시 조정은 ADR-0012에 있다.

### 6.3 기록

1·2단계 확인 결과와 로컬 대회 결과는 `ai/docs/contest-validation/`에 JSON으로 남기고, 요약을 ADR-0012 결과 절에 적는다.

## 7. 채점 (ADR-0002, ADR-0003)

```
수익률 점수 = GENERAL 누적수익률의 백분위
안정성 점수 = 0.6 × 평균(BULL, BEAR, SIDEWAYS 각각의 MDD 백분위) + 0.4 × 최저(같은 셋)
총점       = w × 수익률 점수 + (1 − w) × 안정성 점수
백분위     = (n − 순위) / (n − 1) × 100   # 순위 1 = 가장 좋은 성적 (수익률은 높을수록, MDD는 낮을수록)
                                          # 실격자 제외, 동점은 평균 순위
```

- **실격:** 4개 데이터셋 중 하나라도 수익률 -30% 미만이거나 MDD 50% 초과면 실격이다. `GENERAL`의 평균 투자 비중이 하한보다 낮아도 실격이다.
- **평균 투자 비중:** 평가 구간 equity의 `1 − 현금 / 총자산` 평균이다.
- **기본값:** `w = 0.5`, 투자 비중 하한 30%. 로컬 대회 결과를 보고 조정한다.
- **로컬 대회 참가 전략:** 균등 보유, 모멘텀 2종, RSI 평균회귀, 추세 필터, 저변동성, 거래량 급증, 낙폭 매수, 그리고 실격 규칙이 동작하는지 보려는 몰빵과 현금 대기까지 10개다. 모두 팩터 기간 상한 안에 있다.

## 8. 미결 사항

1. **원본 위치.** 2018~2025 데이터가 있는 DB를 확인해야 한다.
2. **`w`와 투자 비중 하한.** 로컬 대회 결과를 보고 정한다.
3. **블록 자르는 요일.** 4단계에서 정한다.
4. **가상 날짜.** 2030년 시각이 백엔드 검증에 걸리지 않는지 로컬 대회에서 확인한다. 백테스트 요청 DTO와 `trading.backtest_run` 제약에는 미래 날짜를 막는 규칙이 없다.
5. **1원 미만 종목.** 백엔드 기본 설정 `backtest.execution.price-tick-size: 1` 때문에 가격이 1원보다 작은 종목의 체결 계산이 어긋날 수 있다. 로컬 대회에서 확인한다.
6. **화면 설계.** `30-대회 목록`, `31-대회 상세`의 연습용 장세 영역을 고치고, 팩터 기간 상한을 보여 달라고 요청한다.
7. **백엔드 요청.** ADR-0006의 migration, 대회용 provider, 캔들 변환 팩토리와 ADR-0013의 제출 시 팩터 기간 검증.

## 9. 대회 규칙 문구 (초안)

> 채점 데이터는 실제 과거의 한 주들을 뽑아 새 순서로 이어 붙인 시장입니다. 한 주 안의 움직임은 실제 그대로이고, 상승 주 다음에 상승 주가 오는 비율 같은 흐름은 실제 과거를 따릅니다. 상승장은 실제 상승 주들만 모은 것입니다. 채점 데이터는 마감 후 공개합니다.
>
> 대회 데이터에는 평가 시작 전 35일치만 제공합니다. 지표 기간은 1시간봉 839, 4시간봉 209, 일봉 34까지 쓸 수 있고, 이보다 긴 기간을 쓴 전략은 제출할 수 없습니다.
