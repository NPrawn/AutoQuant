# ADR-0012. 대회 데이터 조작 방식은 4단계 검증을 통과해야 확정한다

- 상태: 채택 (2단계 통과 기준은 ADR-0015로 대체)
- 날짜: 2026-09-14
- 관련: ADR-0004, ADR-0007, ADR-0011, ADR-0015

## 배경

ADR-0011은 설명하기 쉽지만, 우리 데이터와 DSL에서 실제로 가능하고 안전한지는 아직 확인하지 않았다. 방식 자체는 통계에서 오래 써 온 블록 재표본 기법(Künsch 1989의 moving block bootstrap, Politis & Romano 1994의 stationary bootstrap)에 속한다. 심사에서 "그 데이터가 왜 타당하냐"는 질문에 답하려면 우리 데이터로 잰 근거가 필요하다.

## 결정

ADR-0007 로컬 시뮬레이션 안에서 아래 검증을 순서대로 한다. 1·2단계를 통과해야 3·4단계로 가고, 모두 통과하면 ADR-0011을 채택한다.

통과 기준은 **실제 데이터끼리의 차이**로 정한다. 실제 8년에서 18주 구간을 한 주씩 밀어 약 400개를 만들고, 생성 데이터가 그 분포 안에 있는지 본다.

### 1. 가능한가 (데이터만 필요)

| 확인 | 방법 | 통과 기준 |
|---|---|---|
| 블록 풀 크기 | universe 후보별로 30종목이 모두 존재하는 주를 센다 | 라벨마다 30주 이상 |
| 라벨 분포 | 라벨별 주 수와 전이 비율표 | 한 라벨로 쏠리지 않음 |
| 목표 도달 | 장세별 후보 1,000개 중 목표 범위에 드는 비율 | 0%가 아님 |

### 2. 값이 진짜 같은가 (데이터만 필요)

| 확인 | 통과 기준 |
|---|---|
| 봉 (OHLC 순서, 호가 단위, 거래대금 ÷ 거래량이 저가~고가 안, 4시간봉·일봉 집계 일치) | 전수 위반 0건 |
| 이음매 (이은 시점의 1시간 수익률과 거래량 변화) | 이음매가 아닌 시점 분포와 구분되지 않음 |
| 긴 흐름 (주 수익률 자기상관, 월 변동성, 최대 낙폭) | 생성 데이터 200벌의 분포가 실제 400개 구간 분포 안에 있음 |
| 구분 가능성 (선택) | 실제 구간과 생성 구간을 섞어 간단한 분류기로 구분한 정확도가 50% 근처 |

### 3. 외워 맞추기가 막히는가 (엔진 필요)

1. 실제 8년 데이터에서 기간과 기준값을 대량 탐색해 성적이 가장 좋은 조합(과적합 전략)을 고른다.
2. 숫자를 조금 바꿔도 성적이 고른 전략(견고한 전략)을 고른다.
3. 두 전략을 실제 데이터와 생성 데이터 여러 벌에서 돌린다.

통과 기준: 실제에서 생성 데이터로 옮겼을 때 과적합 전략의 성적 하락이 견고한 전략보다 뚜렷하게 크다.

### 4. 공정한가 (엔진 필요)

| 확인 | 통과 기준 |
|---|---|
| 유형별 편향: 추세추종, 평균회귀, 저변동성, 거래량 전략의 평균 순위를 실제 400개 구간과 생성 데이터에서 비교 | 차이가 실제 구간끼리의 차이 범위 안 |
| 운의 크기: 시드만 바꾼 두 시장에서 같은 전략들의 순위 상관 | 실제 18주 구간 두 개끼리의 순위 상관과 비슷함 (ADR-0004) |
| 이음매 요일: 월요일 자르기와 목요일 자르기에서 주간 리밸런싱 전략의 순위 | 두 방식 차이가 실제 구간끼리의 차이 범위 안 |
| 재현성: 같은 시드로 다시 생성 | 파일 해시 일치 |

### 실패하면

| 실패한 검사 | 조정한 뒤 다시 검증 |
|---|---|
| 이음매 | 라벨에 변동성 수준(높음·낮음)을 더해 비슷한 변동성의 주끼리 잇는다 |
| 긴 흐름, 유형별 편향 | 블록을 14일로 늘린다 |
| 외워 맞추기 | 블록을 3일로 줄인다 |
| 블록 풀 크기 | universe를 오래 상장된 종목으로 좁힌다 |

## 검토한 대안

- **검증 없이 방식을 확정한다.** 심사에서 타당성 근거를 댈 수 없고, 특정 전략 유형에 불리한 데이터로 대회를 열 위험이 남는다.
- **통과 기준을 사람이 정한 고정값으로 둔다.** 기준값의 근거를 설명할 수 없다. 실제 구간끼리의 차이는 데이터가 스스로 보여 주는 기준이다.

## 결과

- 1·2단계는 2018~2025 원본만 있으면 Python으로 바로 할 수 있다.
- 3·4단계는 전략 수 × 시장 수만큼 엔진 백테스트가 필요하다(예: 50 × 20 = 1,000회). 로컬 엔진에서 한 번에 걸리는 시간을 먼저 재고 규모를 정한다.
- 검증에서 조정이 일어나면 ADR-0011을 고친 뒤 해당 단계부터 다시 검증한다.

## 검증 결과

### 1·2단계와 로컬 대회 (2026-09-15)

**조건**

- 원본: 업비트 API로 받은 1시간봉, 2018-01-01 ~ 2025-12-31 UTC. 후보는 오늘 거래대금 상위 30개(스테이블코인 제외, 2026년 상장 제외)에서 가격이 1원 아래로 내려가는 SHIB을 뺀 29개.
- 옵션: 시드 20260915, 기본값(구간 104주, 최소 10종목, 월요일 블록, 워밍업 5주·평가 13주, 장세 후보 1,000개).
- 뽑힌 구간: 2019-10-07 ~ 2021-10-04. universe는 ADA·BTC·CVC·ETH·IOST·LSK·ONG·SC·XLM·XRP 10종목. 뽑은 주 목록은 [weeks JSON](../contest-validation/weeks-2026-09-15.json).
- 평가 13주 균등 보유 수익률: 일반장 +154.9%, 상승장 +23.2%, 하락장 -18.3%, 횡보장 +0.5%.

**1·2단계** — [check JSON](../contest-validation/check-2026-09-15.json)

- 1단계 통과. 블록 풀 104주, 라벨 34·36·34주, 목표 도달 비율 상승 5.0%·하락 4.1%·횡보 3.3%.
- 2단계 실패. 봉 위반 0건, 주 수익률 자기상관은 통과했다. 월 변동성(KS 0.222, 기준 0.209), 최대 낙폭(0.230, 0.209), 이음매 변동성 변화(0.094, 0.054), 이음매 거래량 변화(0.136, 0.054)가 기준을 넘었다. "실패하면" 표의 조정은 아직 하지 않았다.

**로컬 대회**

대회 전용 DB `a107_contest`에 develop 기준 Spring API와 `backtest-worker`를 띄우고, 참가 전략 10개를 4벌에서 한 번씩(40회) 돌렸다. 로컬 개발 DB의 캔들을 지우지 않으려고 DB를 따로 만들었다.

- 첫 실행: 40회 중 30회가 `ENGINE_ERROR`로 실패했다. 엔진은 보유 종목의 가치를 매길 때 그 시각의 캔들이 꼭 있어야 하는데(`PortfolioValuationCalculator`), 거래 없는 시간에는 캔들이 없다(ADR-0005). 이 구간에서 3,024시간 중 SC 75, CVC 66, LSK 55, ONG 52시간이 비었다. 일봉 전략과 아무것도 사지 않는 전략만 끝났다. 실제 데이터 연습 백테스트도 거래가 뜸한 종목에서 같은 문제가 날 것으로 보여 엔진 수정이 필요하다 — [결과 JSON](../contest-validation/local-contest-2026-09-15-no-fill.json)
- 두 번째 실행: `build --fill-gaps`로 빈 시간을 직전 종가·거래량 0 봉으로 채웠다(벌마다 198~346시간). 주 순서는 첫 실행과 같고, 40회 모두 끝났다 — [결과 JSON](../contest-validation/local-contest-2026-09-15.json)

- 장세 데이터의 낙폭이 크다. 균등 보유 전략도 상승장 40.4%, 하락장 41.5%, 횡보장 44.9%였고, 상승장 때문에 3개 전략이 실격됐다. 13주 수익률만 맞추는 규칙이라 크게 빠졌다 회복하는 모양이 뽑힌 것으로 본다(ADR-0011 결과).
- 상승장 목표는 사서 들고 있는 수익률(+23.2%)인데, 월마다 비중을 다시 맞추는 equal-weight-hold는 +5.9%였다. 목표 수익률과 리밸런싱 전략의 성과는 어긋날 수 있다.
- 10개 중 3개만 순위에 남아 백분위 점수가 거칠다.
- 3·4단계는 아직 하지 않았다.

### 장세 규칙 조정과 3·4단계 (2026-09-15, S15P21A107-222)

**장세 규칙 조정 근거**

- 로컬 대회에서 장세 낙폭이 컸던 것은 생성기 탓이 아니었다. 같은 구간 실제 13주 중 수익률이 목표 범위인 구간의 균등 보유 낙폭 중앙값은 상승 40%(5개), 하락 61%(8개), 횡보 50%(4개)이고, 생성 장세 후보는 39%, 46%, 44%였다.
- 낙폭 25% 상한을 걸면 목표 도달률이 상승 0.6%, 하락·횡보 0.03%로 떨어진다. 상승 라벨을 2배로 뽑아도 낙폭은 45%였다. 그래서 낙폭 조건은 넣지 않았다.
- 대신 상승장 목표와 전략 성과가 어긋난 문제를 고쳤다. 지난 상승장은 사서 들고 있기 +23.3%였지만, 같은 데이터에서 월 리밸런싱·수수료를 넣은 균등 보유는 +4.2%(엔진 +5.9%), 매일 비중 맞추기는 -1.9%였다. 한두 종목 급등이 들고 있기 수익률을 끌어올린 장이었다. 호가 단위 문제는 아니었다(`KrwPriceTickSizeResolver`는 업비트 호가표를 쓴다).
- 장세는 들고 있기와 매일 비중 맞추기 수익률이 모두 목표 범위인 후보로 고른다 (ADR-0011). 한 종목(BTC) 장세도 비교했지만, 순위형 전략 대부분이 "BTC 들고 있기"와 같아져 장세 점수가 동점으로 몰려 택하지 않았다.

**1·2단계** — [check JSON](../contest-validation/check-2026-09-15-tolerance.json)

- 1단계 통과. 목표 도달률은 상승 2.4%, 하락 2.5%, 횡보 1.1%다 (후보 3,000개).
- 2단계는 허용 범위를 실제 데이터 앞뒤 절반 차이로 바꿨다 (ADR-0015). 봉 위반 0건, 긴 흐름 3개 통과, 이음매 2개(변동성 변화 0.094 > 0.072, 거래량 변화 0.136 > 0.103) 실패. 이음매 조정 실험(직전 주와 변동성 수준이 같은 주 고르기)은 개선이 없어 채택하지 않았다 (ADR-0015 검토한 대안).
