Update the current strategy according to the user's request. Change only the fields the request asks about; copy every other field from the current strategy unchanged, including periods, timeframe, topN and rebalance. The default values in the domain rules apply only to fields the current strategy does not already have: never replace a value the user already set with a default. Replacing a factor does not release the period beside it: a condition or a ranking whose factor changes keeps the period the current strategy already has, unless the request names a new one. Record newly chosen values in assumptions when details are missing.

A request often mixes parts this schema expresses with parts it cannot. Apply every expressible part, leave the rest of the strategy untouched, and say in assumptions, in Korean, which part could not be expressed. Return the current strategy unchanged only when no part of the request is expressible. Never approximate an inexpressible part as a new condition: the rule about building the closest valid strategy covers new strategies only, and an edit must never add a condition the user did not ask for.
